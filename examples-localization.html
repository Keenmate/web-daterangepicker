Every UI string goes through core /locale. Keys are flat <elementType>.<name> (buttons.today, labels.days, ariaLabels.clear, …) — the full list is the labels property in API.md. Per key: the instance labels (short or full web-daterangepicker. key) → the element's own translateCallback → the page-wide translateCallback → the page dictionary window.components.locale.labels → the built-in English. The page-wide toggles (LO08, LO09, LO11, LO12) are page-wide: they change every picker on this page, on purpose.

LO01 · Instance labels

Override texts on ONE element with the labels property (or a JSON labels attribute). A short key (buttons.today, labels.days) and a full key (web-daterangepicker.buttons.clear) both work; every key you leave out stays English. {count} is interpolated (locale-formatted). The neighbour picker is untouched.

rendered strings

  

  
el.labels = {
  'buttons.today': 'Dnes',                          // short key
  'labels.days': '{count} dní',
  'web-daterangepicker.buttons.clear': 'Vymazat',   // full key
};
// or declaratively
<web-daterangepicker labels='{"buttons.today":"Dnes","labels.days":"{count} dní"}'></web-daterangepicker>









  
LO08 · Page-wide dictionary

  
One flat dictionary on window.components.locale.labels — the app's translation JSON as loaded, full keys
    'web-daterangepicker.<elementType>.<name>', other components' keys side by side — translates
    every picker on the page at once. Assigning window.components.locale re-renders the live pickers (selection
    kept). Keys an instance set itself (LO01) still win.

  

    
  

  

    

      

        
        
      

      

        
        
      

    

    
rendered strings

  

  
// e.g. const labels = await (await fetch('/i18n/cs.json')).json();
window.components.locale = {
  labels: {
    'web-daterangepicker.buttons.today': 'Dnes',
    'web-daterangepicker.buttons.clear': 'Vymazat',
    'web-daterangepicker.buttons.now': 'Teď',
    'web-daterangepicker.labels.day': '{count} den',
    'web-daterangepicker.labels.days': '{count} dní',
    'web-daterangepicker.labels.night': '{count} noc',
    'web-daterangepicker.labels.nights': '{count} nocí',
    'web-daterangepicker.labels.time': 'Čas',
    'web-multiselect.placeholders.search': 'Hledat…',   // other components share the same JSON
  },
};









  
LO09 · translateCallback

  
An app with its own i18n (i18next, FormatJS, …) answers keys through a callback instead of a dictionary. It gets
    { component, key, template, params, locale } — key is the full
    web-daterangepicker.<elementType>.<name> — and returns the text, or null = not mine.
    The element's own translateCallback is asked first (German, only buttons.today here); its
    null passes the key on to the page-wide one (a small Slovak i18next-like lookup). A key the instance
    labels set (the second picker's buttons.today) is never sent to any callback.

  

    
    
  

  

    

      

        
        
      

      

        
        
      

    

    
rendered strings

  

  
// an i18next-like lookup: a dictionary + t(key, params)
const sk = {
  'web-daterangepicker.buttons.today': 'Dnes',
  'web-daterangepicker.buttons.clear': 'Vymazať',
  'web-daterangepicker.labels.days': '{{count}} dní',
};
const t = (key, params) => sk[key]?.replace(/\{\{(\w+)\}\}/g, (_, p) => params?.[p] ?? '');
const exists = (key) => key in sk;

// page-wide — every component on the page
window.components.locale = { translateCallback: ({ key, params }) => (exists(key) ? t(key, params) : null) };

// one element — asked BEFORE the page-wide callback; null = not mine
el.translateCallback = ({ key }) => (key === 'web-daterangepicker.buttons.today' ? 'Heute' : null);









  
LO10 · Screen-reader name / tooltip follow

  
An ariaLabels.x / tooltips.x nobody set takes the first customized key of the same
    <name>, so translating one string of a pair translates its twin. Here: translate only the footer
    caption buttons.clear — the input's inline ✕ button is named by ariaLabels.clear, which
    nobody set, and it follows. The box below reads the ✕'s aria-label from the shadow root. (The picker has
    no tooltips.* keys; ariaLabels.close has no visible twin.)

  

    
  

  

    
    
    
accessible name of the input ✕ button

  

  
el.labels = { 'buttons.clear': 'Vymazat' };
// → footer button "Vymazat" AND the input ✕ aria-label "Vymazat" (ariaLabels.clear was never set)
// an explicitly set ariaLabels.clear always wins over the twin









  
LO11 · locale + formatting

  
The element's language — the locale input → the page window.components.locale.locale →
    the browser — drives the shown date format (with no date-format-mask:
    cs 15. 06. 2026, de 15.06.2026, en-US
    06/15/2026; a page-wide window.components.locale.dateFormat or an explicit mask wins; the
    submitted value stays ISO), the Intl month / weekday names, the week start
    under week-start-day="auto" and the numbers in {count} labels.

  
page locale

</script>

LO12 · shouldEscapeLabels

  
Labels rendered as HTML (the summary labels.day(s) / labels.night(s) /
    labels.preview, the time-picker captions) are templates: the template's own <b> renders
    bold, while a {param} is DATA and always escaped (a typed <i>Ann</i> would show
    its tags as text — here the only param is the number {count}). With
    window.components.security.shouldEscapeLabels the whole label is text: the template's <b>
    shows as characters too (for apps whose translators must not inject markup). Buttons and aria names are always text.

  

    
  

  

    
    
    
the summary: markup → shown text

  

  
el.labels = { 'labels.days': '<b>{count}</b> days' };
// → <b>5</b> days   (bold)
window.components.security = { shouldEscapeLabels: true };
// → &lt;b&gt;5&lt;/b&gt; days   (the whole label is text)






  Component extras below (LO02–LO07): week start and custom names. The month-names and
  weekday-names HTML attributes take a pipe-delimited (|) list, and the
  monthNames / weekdayNames JS properties take a string array.
  When both are set, the property wins.





  Indexing is fixed to the JS date number, not the visible order:
  month-names is [0]=January … [11]=December (matches
  Date.getMonth()), and weekday-names is always authored Sunday-first:
  [0]=Sunday … [6]=Saturday (matches Date.getDay()).
  week-start-day only rotates the display — you never re-order the list.






  
LO02 · Week Start Day

  
week-start-day takes auto (locale-based) or 0–6
    (0=Sunday … 6=Saturday). It rotates which day column comes first — the
    day cells underneath stay aligned.


  

    

      
      
    

    

      
      
    

    

      
      
    

  







  
LO03 · Custom Weekday Names v2.0

  
The weekday-names attribute overrides the header labels with a pipe-delimited list of
    exactly 7 entries, authored Sunday-first. Here the same Czech list
    Ne|Po|Út|St|Čt|Pá|So is reused across three different start days — note you
    never re-order the list; the component rotates it and the labels stay glued to the right days.

week-start-day="3"

LO04 · Custom Month Names v2.0

  
The month-names attribute overrides month labels with a pipe-delimited list of exactly 12
    entries, in calendar order ([0]=January … [11]=December). No rotation —
    the list is always January → December.


  

    

      
      
      June → "Červen"
    

    

      
      
      June → "06"
    

  


  
<web-daterangepicker
month-names="Leden|Únor|Březen|Duben|Květen|Červen|Červenec|Srpen|Září|Říjen|Listopad|Prosinec"></web-daterangepicker>







  
LO05 · Full Czech Calendar

  
Combine labels, week-start-day, month-names, and
    weekday-names for a fully localized picker (or just locale="cs" for the names). Czech convention starts the week on Monday.


  

    
    
  







  
LO06 · Setting Names via JavaScript

  
The same overrides are available as array properties — useful when the names come from a translation
    bundle at runtime. The property wins if an attribute is also present.


  

    
    
  


  
const el = document.getElementById('js-names');

// [0]=January … [11]=December
el.monthNames = ['Styczeń','Luty','Marzec','Kwiecień','Maj','Czerwiec',
               'Lipiec','Sierpień','Wrzesień','Październik','Listopad','Grudzień'];

// [0]=Sunday … [6]=Saturday
el.weekdayNames = ['Nd','Pn','Wt','Śr','Cz','Pt','So'];







  
LO07 · Validation & Fallback

  
A pipe list must have exactly 12 (months) or 7 (weekdays) non-empty segments.
    A wrong count or an empty segment is ignored — the picker falls back to locale
    names and emits a console.warn naming the attribute. Open your DevTools console to see it.


  

    
    
  


  
// Console output:
// [web-daterangepicker] "weekday-names" ignored: expected exactly 7
//   pipe-delimited segments, got 3. Falling back to locale names.
