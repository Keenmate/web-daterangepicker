EV01 · Events Fired by the Component

The date picker fires these custom events:

Event Names:
  • change - The selection was committed (a pick in commit-mode="selection", Apply / commit() otherwise)
  • open / close - The calendar popover opened / closed (any reason)
  • action - An action button (built-ins too) or a data-action trigger was clicked (detail.action, detail.id, detail.source, detail.dataset)
  • month-change - The visible month(s) changed (detail.monthIndex, year, month, visibleMonths)
  • ready - The picker was built for the first time

Note: All events bubble from the <web-daterangepicker> element (they are not composed). Every detail also carries controller (the picker facade) and element (the host); both are non-enumerable, so JSON.stringify(detail) shows only the data.

Handler properties: as an alternative to addEventListener, assign onChange, onOpen, onClose, onAction, onMonthChange or onReady. Each receives the event detail (not the CustomEvent): el.onChange = (detail) => detail.date. Assign null to detach.

Event Detail Structure

// Single mode
{
  formattedValue: "2025-11-17",
  date: Date object
}

// Range mode
{
  formattedValue: "2025-11-17 - 2025-11-24",
  dateRange: { start: Date, end: Date },
  enabledDates: [Date, Date, ...],    // If using 'allow' mode
  disabledDates: [Date, Date, ...],   // If using 'allow' mode
  dateRanges: [DateRange, ...],       // If using 'split' mode
  dates: [Date, Date, ...],           // If using 'split' or 'individual' mode
  getEnabledDateCount: () => number,  // Helper function
  getTotalDays: () => number          // Helper function
}

Listening to Events

// Listening to events
const picker = document.getElementById('my-picker');

picker.addEventListener('change', (event) => {
  console.log('Date selected:', event.detail);

  if (event.detail.date) {
    // Single mode
    console.log('Selected date:', event.detail.date);
  } else if (event.detail.dateRange) {
    // Range mode
    console.log('Selected range:', event.detail.dateRange);
  }
});

// Handler property: receives the detail directly
picker.onChange = (detail) => console.log(detail.formattedValue);

// The popover opened / closed
picker.addEventListener('open', () => console.log('opened'));
picker.addEventListener('close', () => console.log('closed'));

// Month navigation
picker.addEventListener('month-change', (event) => {
  const { year, month, monthIndex } = event.detail; // month is 0-11
  console.log(`Column ${monthIndex} now shows ${year}-${month + 1}`);
});

EV02 · beforeSelectCallback - Validation & Control

The beforeSelectCallback(ctx) callback is invoked BEFORE a selection is finalized. ctx carries the proposal (mode, date in single mode, range in range mode, plus subRanges / enabledDates under split/individual handling), controller, element and markRangeInvalid(). It allows you to validate, block, adjust, or clear selections based on your business logic.

Key Features:
  • Works for both single and range modes
  • Supports synchronous and asynchronous validation
  • Can reject, adjust, or clear selections
  • Explain a decision with ctx.controller.showMessage(text, { variant })
  • Shows loading overlay during async operations
  • Called AFTER local validation (disabled dates, min/max) passes

Return Values

Return Description Use Case
nothing (undefined) Allow the selection as-is Validation passed
false Reject and revert to the previous selection (call ctx.markRangeInvalid() first to keep a rejected range visible with error styling) Validation failed, keep previous state
a Date / { start, end } Accept this adjusted selection instead Round to business days, snap to availability
DateRange[] Replace the proposal with these N ranges (range mode) Split around unavailable days
null Clear the selection entirely Hard reset on validation failure

EV03 · Single Mode - beforeSelectCallback Examples

Try selecting Saturday or Sunday
Only future dates allowed
Weekends auto-adjust to Monday
Simulates API call (500ms delay)

Code Examples

// Block weekends
picker.beforeSelectCallback = ({ date, controller }) => {
  const isWeekend = date.getDay() === 0 || date.getDay() === 6;
  if (isWeekend) {
    controller.showMessage('Weekends not allowed', { variant: 'danger' });
    return false; // reject, keep the previous selection
  }
  // returning nothing accepts
};

// Adjust to next business day
picker.beforeSelectCallback = ({ date, controller }) => {
  const day = date.getDay();
  if (day === 0 || day === 6) { // Sunday / Saturday → Monday
    const adjusted = new Date(date);
    adjusted.setDate(date.getDate() + (day === 0 ? 1 : 2));
    controller.showMessage('Adjusted to Monday', { variant: 'info' });
    return adjusted; // accept this date instead
  }
};

// Async API validation
picker.beforeSelectCallback = async ({ date, controller }) => {
  const response = await fetch('/api/check-date', {
    method: 'POST',
    body: JSON.stringify({ date: date.toISOString() })
  });
  const { available } = await response.json();
  if (!available) {
    controller.showMessage('Date not available', { variant: 'danger' });
    return false;
  }
};

EV04 · Range Mode - beforeSelectCallback Examples

Requires at least 2 nights
Cannot exceed 7 nights. Calls ctx.markRangeInvalid() before returning false to keep the invalid range visible with error styling.
End date must be Sunday (checkout day)
Select more than 5 nights to see custom HTML error with alternatives. Uses ctx.controller.showMessage(html) for full control; its buttons fire the action event.

Code Examples

// Minimum nights requirement
picker.beforeSelectCallback = ({ range, controller }) => {
  const nights = Math.floor((range.end - range.start) / (1000 * 60 * 60 * 24));
  if (nights < 2) {
    controller.showMessage('Minimum 2 nights required', { variant: 'danger' });
    return false;
  }
};

// Adjust end date to checkout day (Sunday)
picker.beforeSelectCallback = ({ range, controller }) => {
  const endDay = range.end.getDay();
  if (endDay !== 0) { // Not Sunday
    const adjusted = new Date(range.end);
    adjusted.setDate(range.end.getDate() + (7 - endDay));
    controller.showMessage('Adjusted to Sunday checkout', { variant: 'info' });
    return { start: range.start, end: adjusted }; // accept this range instead
  }
};

// Async availability check
picker.beforeSelectCallback = async ({ range, controller }) => {
  const response = await fetch('/api/check-availability', {
    method: 'POST',
    body: JSON.stringify({
      start: range.start.toISOString(),
      end: range.end.toISOString()
    })
  });
  const data = await response.json();

  if (data.available) return; // accept
  if (data.suggestedEnd) {
    controller.showMessage('Adjusted to available dates', { variant: 'info' });
    return { start: range.start, end: new Date(data.suggestedEnd) };
  }
  controller.showMessage('Dates not available', { variant: 'danger' });
  return false;
};

// Maximum nights with markRangeInvalid()
// Keeps the rejected range visible with red styling for better visual feedback
picker.beforeSelectCallback = (ctx) => {
  const nights = Math.floor((ctx.range.end - ctx.range.start) / (1000 * 60 * 60 * 24));
  if (nights > 7) {
    ctx.markRangeInvalid();
    ctx.controller.showMessage('Maximum 7 nights allowed', { variant: 'danger' });
    return false;
  }
};

// Custom HTML message with full control
// A button with data-action="custom" data-id="…" fires the 'action' event;
// its other data-* attributes arrive in detail.dataset
picker.beforeSelectCallback = async (ctx) => {
  const response = await fetch('/api/check', { method: 'POST', body: JSON.stringify(ctx.range) });
  const data = await response.json();

  if (!data.available) {
    // Show fully custom HTML message (no type = raw HTML)
    ctx.controller.showMessage(`
      <div style="background: #fef2f2; ...">
        <div style="color: #991b1b;">Dates not available</div>
        <div style="margin-top: 8px;">
          ${data.alternatives.map(alt => `
            <button data-action="custom"
                    data-id="use-alternative"
                    data-start-date="${alt.start}"
                    data-end-date="${alt.end}"
                    style="background: #dcfce7; ...">
              ${alt.start} - ${alt.end}
            </button>
          `).join('')}
        </div>
      </div>
    `);
    ctx.markRangeInvalid();
    return false;
  }
};

// Handle the action event to apply the chosen alternative
picker.addEventListener('action', (e) => {
  if (e.detail.id !== 'use-alternative') return;
  const { startDate, endDate } = e.detail.dataset; // data-start-date → startDate
  picker.selectedRanges = [{
    start: new Date(startDate),
    end: new Date(endDate)
  }];
  e.detail.controller.hideMessage();
});

EV05 · getMonthDataCallback & beforeMonthChangeCallback - Performance Optimization

getMonthDataCallback(ctx) loads data for the visible range on the initial open and after every month navigation. Use it to bulk-load metadata for all visible dates in ONE API call instead of calling getDateMetadataCallback 35-42 times per month; return { metadata, monthHeaders }. beforeMonthChangeCallback(ctx) runs before a navigation; return false to block it. Both may be async (a loader shows meanwhile) and receive year, month (0-11), monthIndex, firstVisibleDate, lastVisibleDate, plus controller / element. 

// Bulk data for the visible range
picker.getMonthDataCallback = async ({ firstVisibleDate, lastVisibleDate }) => {
  const days = await fetchPricing(firstVisibleDate, lastVisibleDate);
  return {
    metadata: new Map(days.map(d => [d.date, { // key: 'YYYY-MM-DD'
      badgeText: `$${d.price}`,
      isDisabled: d.soldOut
    }]))
  };
};

// Block navigation more than 2 months ahead
picker.beforeMonthChangeCallback = ({ year, month }) => {
  const now = new Date();
  if ((year - now.getFullYear()) * 12 + (month - now.getMonth()) > 2) return false;
};
Performance: 1 API call per month vs 35-42 calls with per-day callbacks
Navigate months to see bulk metadata loading in action. Check console for logs.
Try navigating more than 2 months into the future - navigation will be blocked
Anchor month at index 2 (top-right). Navigation loads all 6 months at once. Try navigating beyond ±3 months to see blocking.

EV06 · Custom Month Headers

Customize the month header text (e.g., "January 2026") to display additional information like room availability, occupancy rates, or any business-specific data.

Two Approaches:
  • getMonthHeaderCallback - Callback to generate header on-the-fly
  • monthHeaders in the getMonthDataCallback result - Return headers with async-loaded data (keys YYYY-MM, 1-based month)

Priority: monthHeaders > getMonthHeaderCallback > default format

Headers show working day counts (excludes weekends & holidays)
Headers loaded with pricing data
Cannot navigate more than 3 months ahead
Headers show occupancy rates with icons

Code Examples

// Approach 1: getMonthHeaderCallback
picker.getMonthHeaderCallback = ({ month, monthName, year }) => {
  const key = `${year}-${String(month.getMonth()).padStart(2, '0')}`;
  const rooms = roomAvailability[key] || 0;
  return `${monthName} ${year} (${rooms} rooms)`;
};

// Approach 2: monthHeaders from getMonthDataCallback
picker.getMonthDataCallback = async ({ year, month }) => {
  const data = await fetchAvailability(year, month);

  const monthHeaders = new Map();
  const monthKey = `${year}-${String(month + 1).padStart(2, '0')}`; // 'YYYY-MM', 1-based
  const monthNames = ['Jan', 'Feb', 'Mar', 'Apr', 'May', 'Jun',
                      'Jul', 'Aug', 'Sep', 'Oct', 'Nov', 'Dec'];
  monthHeaders.set(monthKey, `${monthNames[month]} ${year} (${data.totalRooms} rooms)`);

  return {
    metadata: data.dateMetadata,
    monthHeaders  // Custom headers returned with data
  };
};

EV07 · beforeScrollCallback - the Picker's Own Scrolling

The picker scrolls on its own when a keyboard move brings the focused day into view (source: 'keyboard') and when a time roll centres its value on open ('open') or after a pick ('select') — always through core scrollIntoContainer(), never the page. beforeScrollCallback(ctx) runs first: return false to skip that scroll, or { block, inline, behavior } to replace the defaults. The ctx carries target (day | time), date or timeField + timeValue, item, source, container (null = the page) and options. 

picker.beforeScrollCallback = (ctx) => {
  if (ctx.target === 'day') return { block: 'center' };
  if (ctx.source === 'select') return false; // keep the rolls where the user left them
};
The rolls centre on open; after a pick, the re-centring is skipped.
