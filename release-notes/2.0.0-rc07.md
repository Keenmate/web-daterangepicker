# Web DateRangePicker 2.0.0-rc07 — Release Notes

**Released:** 2026-11-22 · **Pre-release** (`npm install @keenmate/web-daterangepicker@rc`)

These notes cover the changes since **2.0.0-rc06**, the last version on npm. They are the first
release notes for this package; for earlier versions read the
[CHANGELOG](https://github.com/keenmate/web-daterangepicker/blob/prod/CHANGELOG.md).

This rc is the v2 major catching up with the rest of the Keenmate family. The public surface
(attributes, events, callbacks, action buttons, UI strings, the submitted form value) is renamed
and reshaped to the shared Keenmate vocabulary, and the picker's plumbing moves onto
`@keenmate/web-components-core` rc25: core's popover / modal / phone sheet, the shared `/actions`
interaction model, `/locale` labels, `renderIcon`, `renderSlot`, the ARIA grid with roving focus,
and core's lifecycle (`defer` / `ready` / `destroy()`). This is a **major release: breaking, with
no aliases.** Almost every rc06 page needs edits; work through the checklist below.

The exhaustive, per-change list is in
[`CHANGELOG.md`](https://github.com/keenmate/web-daterangepicker/blob/prod/CHANGELOG.md) (section
2.0.0-rc07); this document is the upgrade guide and the highlights.

## Breaking changes

### Attribute and property renames

One vocabulary across the Keenmate components: boolean attributes use the short HTML form
derived from the config key (`is<X>Shown` → `show-<x>`, `is<X>Enabled` → `enable-<x>`,
`should<X>` → `<x>`), properties use the `is` / `should` / `has` prefixes. No aliases.

| rc06 | rc07 |
|---|---|
| `is-summary-shown` | `show-summary` (property `isSummaryShown` unchanged) |
| `is-seconds-shown` | `show-seconds` |
| `is-today-button-shown` / `is-clear-button-shown` / `is-now-button-shown` | `show-today-button` / `show-clear-button` / `show-now-button` |
| `is-unified-navigation-enabled` | `enable-unified-navigation` |
| `is-unified-header-interactive` | `unified-header-interactive` |
| `should-highlight-disabled-in-range` | `highlight-disabled-in-range` |
| `should-close-on-scroll` | `close-on-scroll` |
| `visible-months-count` / `visibleMonthsCount` | `visible-month-count` / `visibleMonthCount` |
| `display-format-mask` / `displayFormatMask` | `placeholder-format-mask` / `placeholderFormatMask` |
| `display-time-format-mask` / `displayTimeFormatMask` | `placeholder-time-format-mask` / `placeholderTimeFormatMask` |
| property `formFieldName` | `name` (attribute unchanged) |
| property `inputValue` | `defaultValue` (attribute `value` unchanged) |
| property `disabled` | `isDisabled` (attribute `disabled` unchanged) |
| property `readonly` | removed — use `isReadonly` (attribute `readonly` unchanged) |

`enable-unified-navigation` and `unified-header-interactive` now read their value:
`="false"` / `"0"` / `"no"` / `"off"` is `false` (rc06 counted any value as `true`, the presence
rule). This matters for frameworks that render `x={flag}` as `x="false"`. `disabled` / `readonly`
keep the presence rule, because the browser reads them that way. The `display-*` masks were only
ever the placeholder hint, which is what the new names say.

### `presentation` replaces the modal positioning mode

"Where the calendar lives" and "how a floating picker opens" are now two separate inputs:

| rc06 | rc07 |
|---|---|
| `positioning-mode="inline" \| "floating" \| "modal"` | `positioning-mode="inline" \| "floating"` |
| `positioning-mode="modal"` | `presentation="modal"` |
| `mobile-modal-breakpoint`, `mobile-modal-min-height` | removed — `presentation="auto"` follows the device |

`positioning-mode="modal"` is now an invalid value: it warns and keeps the previous value
(default `floating`). `presentation` (`auto` | `floating` | `modal` | `fullscreen`, reflects)
applies only to a floating picker. The default `auto` is a device ladder — see
[Phones and tablets open a sheet or a modal](#phones-and-tablets-open-a-sheet-or-a-modal).

### `commit-mode` replaces `auto-close` and `is-apply-button-shown`

The old pair could be set to contradictory combinations (a range picker that closed on
selection yet rendered an Apply button). Committing and closing are now separate axes:
`commit-mode` decides when a pick is written and fires `change`; `close-on-select`,
`close-on-outside-click` and `close-on-scroll` decide when the calendar closes.

| rc06 | rc07 |
|---|---|
| `auto-close="selection"` | `commit-mode="selection"` |
| `auto-close="apply"`, `is-apply-button-shown="true"` | `commit-mode="apply"` |
| `auto-close="never"` | `commit-mode="manual"` (the app calls `el.commit()`) |
| `is-apply-button-shown="false"` | drop it (`selection` / `manual` have no Apply button) |
| "commit at once, stay open" | `commit-mode="selection" close-on-select="false"` |

- `selection` (default for date mode) writes every completed pick; `apply` (default for
  `time` / `datetime` and `selection-mode="multiple"`) stages picks until Apply / Enter /
  `commit()`; `manual` stages until the app calls `commit()` and has no built-in button.
- **rc06 showed an Apply button by default in range mode** (`is-apply-button-shown` defaulted to
  `true` for `range` and `multiple`). A date-mode range picker now defaults to `selection` — no
  Apply button. Set `commit-mode="apply"` to keep it.
- A staged change (a pick, a typed date, an emptied text or ✕ clear) is **discarded** when the
  calendar closes without a commit, on Escape, and when the focus leaves the field (input +
  calendar) — also while the calendar is closed. Discard restores the selection, the input text,
  the ✕ and the placeholder to the committed value and fires no `change`.
- `close-on-outside-click` defaults to `true` (`false` in `manual` unless set) and covers the modal
  backdrop; Escape and `close()` always close.

### Removed inputs and methods

| rc06 | rc07 |
|---|---|
| `el.show()` / `el.hide()` | `el.open()` / `el.close()` (`toggle()`, `isOpen` unchanged) |
| `el.getInputValue()` / `el.setInputValue(x)` | `el.value` |
| `el.setMonthNames(names)` | `el.monthNames = names` |
| `el.toggleMessage()` / `el.toggleLoader()` | `showMessage()` / `hideMessage()`, `showLoader()` / `hideLoader()` |
| `el.picker` (the raw engine) | `el.controller` (the typed facade) |
| `enable-transitions` / `enableTransitions` | removed — animations are on by default |
| `show-debug-info` / `showDebugInfo` | removed — `el.enableLogging()`, `window.components['web-daterangepicker'].logging.setLogLevel('debug')`, or `window.components.logging` |
| `customStrings` | `labels` ([table](#ui-strings-are-one-labels-object)) |

To turn animations off, set `--drp-transition-fast: 0s; --drp-transition-normal: 0s` on the
component or `--base-duration-*: 0s` page-wide; `prefers-reduced-motion: reduce` already does.

### Events: `change` and `action`

Events follow the shared Keenmate interaction model (core `/actions`).

| rc06 | rc07 |
|---|---|
| `date-select` + `change` (same moment, same detail) | `change` only (`ChangeEventDetail`) |
| `custom-action` `{ data, picker, controller }` — custom buttons only | `action` — every button (built-ins too) and every `data-action` trigger; detail `{ action, id, item, source, sourceEvent, triggerElement, dataset, controller, element, … }` |
| `el.onDateSelect = (e) => e.detail…` | `el.onChange = (detail) => …` — every `on*` twin receives the **detail** |
| `composed: true` | `composed: false` (bubbles on the host) |

`date-select` fired at exactly the same moments as `change` with the same detail, so it is gone
rather than renamed. Every detail carries `controller` and `element` as non-enumerable fields, so
`JSON.stringify(detail)` and LiveView `pushEvent` see only the data. Listeners on the element or
its ancestors are unaffected by `composed: false`.

### Callbacks renamed and reshaped

| rc06 | rc07 |
|---|---|
| `beforeDateSelectCallback` → `{ action: 'accept' \| 'adjust' \| 'restore' \| 'clear', adjusted*, message, showInvalidRange }` | `beforeSelectCallback(ctx)` → nothing (accept), `false` (reject), a `Date` / `DateRange` (adjust), `DateRange[]` (N ranges), `null` (clear); messages via `ctx.controller.showMessage(…)`, `ctx.markRangeInvalid()` replaces `showInvalidRange` |
| `beforeMonthChangedCallback` → `{ action: 'accept' \| 'block', metadata, monthHeaders, message }` | `beforeMonthChangeCallback(ctx)` → `false` blocks; month data moved to `getMonthDataCallback(ctx)` → `{ metadata?, monthHeaders? }` (initial open + every navigation) |
| `badgeTooltipCallback` / `dayTooltipCallback` | `getBadgeTooltipCallback` / `getDayTooltipCallback` |
| `formatSummaryCallback(ctx)` → string | `renderSummaryCallback(ctx)` → core's render result ([details](#render-callbacks-follow-cores-result-contract)) |
| `customStylesCallback()` | `getCustomStylesCallback(ctx)` |
| `getValueFormatCallback(selection)` | `getValueFormatCallback(ctx)` — same fields + context |

Contexts: `ctx.picker` (the raw engine) is gone — every context carries `controller`, `element`
(the host) and the presentation flags (`presentation`, `isModal`, `isFullscreen`).
`DayContext.element` (the day cell) is `cellElement`; `SummaryContext.rangeDisabledHandling` is
`disabledDatesHandling` (it now matches the runtime). `SummaryContext.localeStrings` is
`ctx.labels`, a `{ text(key, params), html(key, params) }` view over the full label chain, with
numbers locale-formatted:

```js
// rc06
ctx.localeStrings.days            // a bare word; the callback built the count itself
// rc07
ctx.labels.html('labels.days', { count: ctx.days })   // innerHTML (params escaped); .text() for plain text
```

### Render callbacks follow core's result contract

`renderDayCallback`, `renderDayContentCallback` and `renderSummaryCallback` read their result by
core's one rule (`renderSlot`): a string is HTML, a Node is mounted, `null` / `undefined` draws the
default, `false` hides it.

| Callback returns `false` | rc06 | rc07 |
|---|---|---|
| `renderDayCallback` | ignored, the day number showed | the day's content is empty (the cell stays clickable) |
| `renderDayContentCallback` | nothing added | the day's content is hidden, number included |

`renderDayContentCallback`'s content now sits in a `.drp__day-extra` box (`display: contents`)
after the number; a selector that expected it as a direct child of the day's `<slot>` needs the
extra step.

### Action buttons are core action items

`ActionButton` is core's `ActionItem` (`DateRangePickerActionItem`):

| rc06 | rc07 |
|---|---|
| `{ action: 'custom', text, onClick }` | `{ id: 'my-id', text, onClick }` — `action` only for the built-ins `today` / `now` / `clear` / `apply`; string shorthand `'today'` |
| `isVisibleCallback` / `isDisabledCallback` | `getIsVisibleCallback` / `getIsDisabledCallback` |
| `onClick(ctx)` — custom buttons only | `onClick(detail)` for every button, built-ins included |
| `custom-action` event before the built-in | order: `beforeActionCallback` → `onClick` → built-in → `action` event (a notification after the fact) |
| `<button data-action="custom" data-x="…">` in `showMessage` HTML → `detail.data` | `data-action="custom" data-id="…"` → `action` event with `source: 'message'`, other `data-*` in `detail.dataset` |
| button text injected as HTML | plain text |

To prevent a built-in, return `false` from `beforeActionCallback` (async is fine; the button is
busy meanwhile). The internal controls (nav arrows, month / year toggles, message ✕) moved to
`data-drp-action`, so page markup can't trigger them.

### UI strings are one `labels` object

`customStrings` and the built-in `de` / `fr` / `es` string tables are replaced by one `labels`
object (property, or JSON attribute `labels='{"buttons.today":"Heute"}'`; partial over English,
exported as `DEFAULT_LABELS`). **There are no built-in translations any more**: `locale` picks the
`Intl` month / weekday names and the date format; translate the strings with `labels`, the
page-wide dictionary or `translateCallback` ([details](#labels-page-wide-dictionary-and-translatecallback)).

Keys are flat `<elementType>.<name>`; the instance takes the short key or the full one
(`web-daterangepicker.buttons.today`). Count strings are templates now (`labels.days` =
`'{count} days'`, was the bare word `days`).

| rc06 `customStrings` key | rc07 `labels` key |
|---|---|
| `today` / `apply` / `now` | `buttons.today` / `buttons.apply` / `buttons.now` |
| `clear` | `buttons.clear` (footer button) + `ariaLabels.clear` (input ✕) |
| `preview` | `labels.preview` |
| `day` / `days` / `night` / `nights` | `labels.day` / `labels.days` / `labels.night` / `labels.nights` (with `{count}`) |
| `time` / `am` / `pm` | `labels.time` / `labels.am` / `labels.pm` |
| `hours` / `minutes` / `seconds` | `labels.hours` / `labels.minutes` / `labels.seconds` |

New keys: `labels.selectionCount` (the multiple-mode input text), `ariaLabels.close` (sheet /
message ✕), `ariaLabels.loading`, `headers.fullscreen` (the phone sheet title) and
`errors.valueFormat`. An `ariaLabels.<name>` you did not set follows a customized sibling with the
same `<name>`: a translated `buttons.clear` also names the input ✕.

### Messages: `showMessage()` options and the `danger` variant

`showMessage(content, type, autoHide)` → `showMessage(content, { variant, autoHideMs })`. The
message kinds are the `--base-*` contract's role names, the same as web-multiselect:
`info` | `success` | `warning` | `danger` (`'error'` → `'danger'`).

| rc06 | rc07 |
|---|---|
| `showMessage(text, 'error', 3000)` | `showMessage(text, { variant: 'danger', autoHideMs: 3000 })` |
| `.drp__message--error` | `.drp__message--danger` |
| `--drp-message-error-bg` / `-color` / `-border` | `--drp-message-danger-bg` / `-color` / `-border` |

### The form value model

Rule for every Keenmate form component: `el.value` is exactly what the form submits; the `value`
attribute is the default (`defaultValue`).

- **`el.value` returns the submitted value**: `2026-06-15/2026-06-20` for a range (rc06: the
  displayed `2026-06-15 - 2026-06-20`), a `string[]` for `value-format="array"`. The setter
  accepts the same form, ISO, or the displayed text.
- **`value` is not reflected**: assigning `el.value` changes the selection, not the attribute;
  `form.reset()` restores the selection parsed from the attribute (rc06 cleared it).
- **`value-format="iso"` → `"text"`** (`text | json | array`; `text` is one field, the default).
- **A range always submits a list of ranges** (one plain range, the pieces of a range split around
  disabled days, or several independent ranges):
  - `json`: `[{"start":…,"end":…}, …]` (rc06: a single `{"start":…,"end":…}` object);
  - `array`: one `name[]` field per range, `start/end` (rc06: two fields per range, start and end);
  - `text`: `start/end` per range, ranges joined by `,` (unchanged).
- A range inside `multiple` mode is an object in `json` (`{"start":…,"end":…}`, not a pair).
- An empty selection submits `''` in `text` / `json`, no field in `array`.

`value-format-mask` and `value-separator` (new) change how dates are written; the default stays
ISO ([details](#value-format-mask-value-separator-and-validity)).

### An unset `date-format-mask` follows the locale

rc06 showed `YYYY-MM-DD` when no `date-format-mask` was set. rc07 shows the browser's format for
the effective locale (`date-format-mask` is nullable, no default): the page-wide
`window.components.locale.dateFormat` when set, else derived from `Intl` for the element `locale`
→ page locale → browser language (`cs` → `17. 11. 2026`, `de` → `17.11.2026`, `en-US` →
`11/17/2026`). To keep ISO, set `date-format-mask="YYYY-MM-DD"` on the element or
`window.components.locale.dateFormat = 'YYYY-MM-DD'` page-wide. An explicit mask always wins, and
the submitted value is unchanged (ISO). The mask engine now accepts literal text around the parts
(`DD. MM. YYYY`, `YYYY. MM. DD.`), so every locale format types and parses.

### Package exports

The standalone engine class is no longer exported: it drew the same UI without the custom element.
Use `<web-daterangepicker>` (`document.createElement('web-daterangepicker')`); every engine option
the element supports is an element property of the same name.

| rc06 export | rc07 |
|---|---|
| `DateRangePicker` (class) | removed — use the element |
| `DatePickerOptions` | removed — `DateRangePickerConfig` (`Partial<…>` for a subset) |
| `SelectEventDetail`, `DatePickerEventDetail` | `ChangeEventDetail` |
| `CustomActionEventDetail`, `ActionButtonContext` | `DateRangePickerActionEventDetail` |
| `ActionButton` | `DateRangePickerActionItem` |
| `SelectionContext` | `BeforeSelectContext` |
| `LocaleStrings` | `DateRangePickerLabels` |
| `FormValueFormat` `'iso'` | `'text'` |

The tag is defined by `registerComponent()` in the package entry only; importing
`web-component.ts` on its own no longer defines it.

### The loader is the shared core loader

Every loader (`showLoader('calendar' | 'message' | 'summary')` and the overlay around async
callbacks) is drawn by core `renderLoader()`: the new `renderLoadingCallback` property, else the
page-wide `window.components.renderLoadingCallback`, else the default `<span class="drp__loader">`
(a single-colour mask shape from the `--base-loader-*` contract).

| rc06 | rc07 |
|---|---|
| border-ring spinner, `drp-spin` keyframe | mask loader, `drp-loader-spin` keyframe |
| `--drp-loader-inline-size`, `--drp-loader-border-width`, `--drp-loader-accent` | removed — `--drp-loader-icon` / `-rotate` / `-duration` / `-size` chain to `--base-loader-*` |
| `--drp-loader-size` (the overlay) | `--drp-loader-size` is the in-block loader (`1.25em`); the overlay is `--drp-loader-overlay-size` (2×) |

The loader container is `role="status"` named by `ariaLabels.loading`.

### CSS variables renamed

| rc06 | rc07 |
|---|---|
| `--drp-opacity-disabled` (fixed 0.6) | `--drp-disabled-opacity` (`var(--base-disabled-opacity, 0.65)`) |
| `--drp-transition-fast` = 150ms | `--drp-transition-fast` = `var(--base-duration-fast, 0.1s)`; the old 150ms speed is `--drp-transition-normal` |
| `--drp-z-index-dropdown` 9500 | `var(--base-z-dropdown, 7500)` |
| `--drp-z-index-modal-backdrop` 9700 / `-modal` 9800 | `var(--base-z-modal-backdrop, 6000)` / `var(--base-z-modal, 7000)` |
| `--drp-z-index-tooltip` 9999 | `var(--base-z-tooltip, 9000)` |

If you set `--drp-transition-fast` for inputs / buttons / nav, set `--drp-transition-normal`
instead. The z-index tiers are the page-wide ones every Keenmate component uses; a page element
that relied on sitting under 9500 may now cover the calendar.

### `data-theme` is the only per-instance theme switch

`data-bs-theme` on the `<web-daterangepicker>` element itself no longer forces its scheme; use
`data-theme`, the switch every Keenmate component shares. Bootstrap's `data-bs-theme` on `<html>`,
`<body>` or a `theme-source` section is unchanged (core detects it).

## Behaviour changes

### Phones and tablets open a sheet or a modal

With the default `presentation="auto"`, a floating picker follows the device (core
`classifyDevice`, capability-based and orientation-robust): a phone (touch-primary, shorter side
< 600px) opens a full-screen sheet, a tablet a centered modal, a desktop the floating popover. In
rc06 a floating picker was a popover on every device unless `mobile-modal-breakpoint` was set. To
keep the popover everywhere, set `presentation="floating"`.

### `readonly` and `disabled` follow native inputs

- `readonly` locks the `selection`, `actions` and `open` aspects but leaves month navigation live,
  keeps the input focusable and submits the value. rc06 locked all four aspects; call `el.lock()`
  for that.
- `disabled` (or a disabled ancestor `<fieldset>`) disables the calendar too: an inline calendar
  turns `inert` and greys out, an open floating calendar closes, and the hidden form inputs are
  `disabled` (not submitted). rc06 disabled only the text input.
- Calls from code keep working under a lock / `readonly` / `disabled`, except opening:
  `open()` / `toggle()` don't open, like a native `showPicker()`.
- `isReadonly` reflects to the `readonly` attribute.

### Invalid attribute values are refused

`input-size` and `calendar-placement` are closed sets, and malformed `week-start-day`,
`disabled-weekdays`, `month-names`, `weekday-names`, `rolling-year-range` are refused through core:
a warning, the `input-rejected` event, and the previous value stays. rc06 dropped some silently,
and `disabled-weekdays="1,9"` kept the good segment; now it is refused whole.

### Closing: scroll, Escape and outside click

- Only a scroll that moves the input (the page, or a scroll container around the picker) closes the
  floating calendar; a scroll of an unrelated panel no longer does.
- Escape closes one level per press: an open year / month selector first, then the picker; while a
  compact time field is being edited, Escape reverts the edit and keeps the calendar open.
- A page control that calls `el.open()` while the calendar is open keeps it open through its click.

### Typing and clearing commit the value

- A complete, valid typed single date commits like a day click: `el.value`, the form field and
  `change` follow, and `beforeSelectCallback` runs for it.
- Emptying the input, the footer Clear and the input ✕ commit the cleared value (`change` fires
  once with `formattedValue: ''`); clearing an already empty value fires nothing.
- `form.reset()` and assigning `value` move the visible month without firing `month-change`, like a
  native reset.

### `locale` reads `null` when unset

The `locale` input has no default: `el.locale` reads `null` (rc06: `'auto'`). Unset means the
page-wide `window.components.locale.locale`, else the browser language — the same result as
before; `locale="auto"` still works. `week-start-day="auto"` follows it.

### Page theme signals

The page theme (`data-theme`, `data-bs-theme`, `.dark` / `.light` on `<html>` or `<body>`) is read
by core and now works in Firefox and Safari (rc06 used `:host-context()`). A signal on a wrapper
element is read only with `theme-source="closest"` (or a selector) on the picker. A per-instance
`data-theme` wins over the page in both directions.

### Logging starts at `warn`

The `DRP:*` loggers start at `warn` (rc06 forced them silent), so warnings — including core's
invalid-attribute warnings — show in the console. `window.components.logging` and
`el.disableLogging()` turn them off.

## New features — presentation

### Phone sheet and modal

The full-screen phone sheet is an edge-to-edge overlay with core's shared sheet chrome (title, 44px
✕ chip), a page-scroll lock, soft-keyboard tracking and a Back-gesture trap (core
`claimBackEntry()`; Back closes the sheet and the page keeps its scroll). The modal is a core modal
session: the page behind is `inert`, Tab stays inside, Escape / Back / the backdrop close it. The
presentation switches in place when the device or orientation changes — the selection survives.

```html
<web-daterangepicker presentation="fullscreen" show-fullscreen-input fullscreen-autofocus></web-daterangepicker>
```

- `show-fullscreen-input` moves the live input into the sheet header (digits keypad, the mask
  supplies the separators); `fullscreen-autofocus` focuses it on open.
- The sheet title is the `headers.fullscreen` label; the bar is themed with `--drp-sheet-*` (the 19
  suffixes every Keenmate sheet uses), the rest with `--drp-fullscreen-*`.

## New features — lifecycle, events and the controller

### `defer`, `ready` and `destroy()`

From core `BlissElement`: the `defer` attribute (`el.shouldDefer`) holds the first build until
`el.release()` (or removing `defer`), so `value`, callbacks and listeners can be wired first. After
the first build: the `ready` attribute, `:state(ready)`, the `ready` event (`onReady`),
`el.isReady` and `el.whenReady()`. `el.destroy()` tears the picker down for good (`el.isDestroyed`).
A DOM move keeps the picker intact — selection, staged picks, open state and shown months survive.

### `el.controller`, `commit()` and new events

- `el.controller` (and `controller` on every context and detail) is a typed, frozen facade: read
  the selection (`selectedDate`, `selectedDates`, `selectedRanges`, `selectedStartDate`,
  `selectedEndDate`, `selectedTime`, `selectedDatetime`, `isOpen`) and drive the picker
  (`open`, `close`, `commit`, `selectToday`, `selectNow`, `clearSelection`, `prevMonth`,
  `nextMonth`, `lock`, `showMessage`, `showLoader`, `reloadMonthData`, …).
- `el.commit()` commits the staged selection (`commit-mode="apply"` / `"manual"`).
- New events: `open` / `close` (the calendar popover, any reason), `month-change`
  `{ monthIndex, year, month, visibleMonths }` after any navigation, `ready`, and
  `value-format-error` — each with its `on*` twin.

### Action buttons: `beforeActionCallback`, `icon`, `shortcut`

Action items take `icon`, `isDanger`, `isToggled` (`aria-pressed`, with `getIsToggledCallback`),
`getIconCallback` and a `shortcut` (`'Mod+T'`, `'Shift+C'`; shown as a keycap, runs the button
while the picker is open). `beforeActionCallback(detail)` returning `false` cancels a click.

```js
el.actionButtons = [
  'today',
  { id: 'next-week', text: 'Next week', icon: 'check', shortcut: 'Mod+N', onClick: (d) => … },
];
```

### `beforeScrollCallback`

Runs before every scroll the picker does on its own (a keyboard day reveal `'keyboard'`, a time
roll centring on open `'open'` or after a pick `'select'`): `false` skips it,
`{ block, inline, behavior }` replaces the defaults.

## New features — forms

### `value-format-mask`, `value-separator` and validity

- `value-format-mask` sets how each submitted date is written (default ISO), and parses the `value`
  attribute / property the same way; `value-separator` joins the dates in `text` (range default
  `/`, multiple `,`). Priority: `getValueFormatCallback` > the masks > `value-format`.
- A throwing `getValueFormatCallback` makes the control invalid (`validity.customError`, the
  `errors.valueFormat` message), so the form refuses to submit; `value-format-error` `{ error, value }`
  fires. Core's validity API is on the element: `validity`, `validationMessage`, `willValidate`,
  `checkValidity()`, `reportValidity()`.

```html
<web-daterangepicker name="stay" selection-mode="range"
  value-format-mask="DD.MM.YYYY" value-separator=" - "></web-daterangepicker>
<!-- submits stay=03.11.2026 - 10.11.2026 -->
```

## New features — localization and icons

### Labels: page-wide dictionary and `translateCallback`

Labels resolve through core `/locale`: instance `labels` → the element's `translateCallback` →
the page-wide dictionary / `translateCallback` → English. Assigning `window.components.locale`
re-renders live pickers (the selection survives).

```js
window.components.locale = {
  locale: 'cs-CZ',
  labels: { 'web-daterangepicker.buttons.today': 'Dnes' },
  translateCallback: ({ component, key, template, params, locale }) => i18n(key, params),
};
el.translateCallback = ({ key }) => myStrings[key];   // this picker only; null = not mine
```

The page-wide locale also drives the week start (`week-start-day="auto"`), the `Intl` month /
weekday names, the shown date format and the `{count}` numbers.

### `renderIconCallback`

Action-button `icon` strings render through core `renderIcon`: markup (`<svg…>`) is inserted raw;
a built-in name (`check`, `close`, `settings`, `delete`, …) draws the masked `--base-icon-*`
glyph; the element's `renderIconCallback(name, ctx)`, then the page-wide
`window.components.renderIconCallback`, may map anything else; a remaining ASCII class name becomes
`<i class="drp__icon fa-solid fa-star">`; anything else is text. Assigning the page-wide hook after
a picker rendered repaints its icons in place.

## New features — accessibility and keyboard

### ARIA grid with roving focus

Each month is a WAI-ARIA `grid` (named by month and year) with `columnheader` weekdays, `row`
weeks and `gridcell` days carrying `aria-selected`, `aria-current="date"` and `aria-disabled`. The
grid is one tab stop: the arrows move real focus between days (disabled and neighbour-month cells
skipped, Left / Right follow the writing direction), **Shift+PageUp / Shift+PageDown** jump a year
and **Space** picks the focused day. A floating calendar still keeps focus in the input on open.

### Day tooltips on focus

The day / badge tooltip (core `createTooltip`) shows on keyboard focus too, not only on hover, is
`role="tooltip"` with `aria-describedby`, and Escape hides it. Tooltips fade in and out
(`--base-duration-fast`).

### Right-to-left and IME

In a `dir="rtl"` context the nav chevrons point outward and ArrowLeft / ArrowRight follow the
visual direction. Typed input is IME-safe: half-composed text is not masked or acted on, and the
Enter that confirms a candidate doesn't pick a day.

## New features — theming and responsive rules

### Page-wide custom CSS

`window.components['web-daterangepicker'].customStyles` (a CSS string; `@import url(…)` works) or
`.getCustomStylesCallback(ctx)` styles every picker on the page; a picker's own `custom-styles`
attribute (new) / `getCustomStylesCallback` comes after it and wins. In dev builds, injected CSS is
linted for `--drp-*` names the component never reads.

### Responsive rules

Every picker takes core's responsive rules: a `{ device, breakpoint, container }` map or a callback
returning a partial config, page-wide (`window.components.responsive*`), per tag or per instance
(`responsive` JSON attribute, `el.responsiveCallback`). The `container` axis reacts to the
element's own width:

```html
<web-daterangepicker
  responsive='{"container":{"narrow":{"visibleMonthCount":1,"isTodayButtonShown":false}}}'>
</web-daterangepicker>
```

### Tooltip width and contract colours

`--drp-tooltip-width` and `--drp-tooltip-min-width` join `--drp-tooltip-max-width` (day, badge and
action-button tooltips). Without `@keenmate/base-css-variables` the picker falls back to the
contract's defaults and formulas, so a standalone `--drp-accent-color` brings its hover and
on-accent text along; with it, the picker reads `--base-primary-*`. All icons are
`--base-icon-*`-chained CSS masks (`--drp-icon-close`, `-clear`, `-chevron`, `-calendar`).

## Visible changes without a migration

- The floating calendar opens **4px** below the input (was 8px): the gap is the page token
  `--base-dropdown-offset`. Keep the old look with `web-daterangepicker { --base-dropdown-offset: 8px; }`.
- `--drp-border-color` defaults to `light-dark(#cbd5e1, #52525b)` (was the near-invisible
  `#e5e7eb` / `#3a3a3a`); the dark surface is `#1e293b` (was `#1a1a1a`); the field outline is its
  own token `--drp-input-border-color`.
- The prev / next arrows, the ✕ and the calendar affordance are icon masks (were characters and
  the `📅` emoji), so they look the same in every font.
- The modal and sheet use dynamic viewport units (`100dvh`), so a tall modal's Apply row no longer
  hides under a phone's URL bar.
- A single-month modal is 360px wide (`--drp-modal-width-single`) instead of the multi-month width.

## Fixes

### Selection and value

- A runtime change to a structural input (`hour-cycle`, `show-seconds`, `visible-month-count`, …)
  keeps the committed selection; a `selection-mode` / `picker-mode` flip carries over what the new
  mode can represent instead of leaving stale text.
- A range `value` is lenient about the separator (`2026-06-10 to 2026-06-14`, an en dash, `bis`).
- `selectedRanges` in range mode returns the selection (it read `[]` for a plain range).
- Opening the calendar on a committed range no longer fires `change`.
- `commit-mode="apply"`: Apply now fires `change` and refreshes the submitted form value.

### Interaction

- `close-on-scroll` no longer closes the calendar right after it opens (the focus scroll).
- Tapping the input no longer opens and instantly re-closes a modal / sheet (the ghost click);
  closing the sheet or modal no longer jumps the page to the top.
- Range drag-to-adjust works with touch (Pointer Events).
- Keyboard navigation scrolls only the calendar, never the page, and no longer leaves two focused
  days; `Home` / `End` move the caret in the input before navigating.
- Safari: the compact time pills are editable.
- Time rolls land instantly when they centre, so a quick click no longer lands between items.

### Smaller

- Several custom action buttons no longer all show the first one's tooltip; `onClick` on a built-in
  button is no longer ignored.
- Attribute values and `data-tooltip` are escaped with core `escapeHtml` (`&` in a tooltip came
  back as `&`).
- The resize close and the document `keydown` listener no longer leak across pickers / rebuilds.
- Dark mode: the sheet ✕ hover and the disabled-day stripes are visible on a dark calendar.
- `rolling-year-range` understands the relative form `-5:+5` (and `2020:+2`).
