AB02 · Modal Display Mode (centered overlay)

Set positioning-mode="modal" to render the calendar as a centered overlay with a backdrop scrim instead of anchoring to the input. Helpful on small screens where multi-month layouts horizontally overflow.

positioning-mode="modal" — click input or button to open
visible-months-count="3" — would overflow horizontally on mobile in floating mode; in modal it fits and scrolls vertically
month-layout="grid" grid-rows="2" grid-columns="3" — six months in a centered grid
positioning-mode="floating" mobile-modal-breakpoint="768px" mobile-modal-min-height="500px" — floating when there's enough room, modal when viewport is too narrow OR too short for a 2-month picker (resize the window to test)
// Centered overlay with backdrop — close via Apply, Escape, or backdrop click <web-daterangepicker selection-mode="range" positioning-mode="modal"></web-daterangepicker> // Open programmatically document.querySelector('#picker').isOpen = true; // CSS variables for theming --drp-modal-gap: 16px; /* viewport-edge gap */ --drp-modal-backdrop-bg: rgba(0, 0, 0, 0.45); /* scrim color */ --drp-modal-transition: 150ms ease-out; /* fade timing */

AB03 · Commit Mode (when the pick commits & the calendar closes)

The commit-mode attribute governs how a selection is committed and the calendar dismissed — it merges the old auto-close and is-apply-button-shown into one axis.

Never auto-commits or auto-closes, and shows no built-in Apply button — you drive close via your own buttons
Commits and closes when selection completes (click, drag-adjust). No Apply button. Multiple mode can't use this
Shows an Apply button; the selection is staged until Apply is clicked, which commits and closes
// Commit modes: 'selection' (default), 'apply', 'manual' <web-daterangepicker commit-mode="selection"></web-daterangepicker> <web-daterangepicker commit-mode="apply"></web-daterangepicker> <web-daterangepicker commit-mode="manual"></web-daterangepicker>

AB07 · Conditional Button Visibility (JavaScript)

Show/hide buttons based on picker state using the getIsVisibleCallback function.

const picker = document.querySelector('#conditional-picker'); picker.actionButtons = [ { action: 'today', text: 'Today' }, { action: 'clear', text: 'Clear' }, { action: 'apply', text: 'Apply', // Only show Apply when both dates are selected getIsVisibleCallback: ({ element }) => element.selectedStartDate && element.selectedEndDate } ];

AB08 · Dynamic Disabled State (getIsDisabledCallback)

Enable/disable buttons dynamically based on picker state.

Apply disabled until both dates selected, Clear disabled when no selection
const picker = document.querySelector('#disabled-picker'); picker.actionButtons = [ { action: 'today', text: 'Today' }, { action: 'clear', text: 'Clear', // Disable Clear when nothing is selected getIsDisabledCallback: ({ element }) => !element.selectedStartDate && !element.selectedEndDate }, { action: 'apply', text: 'Apply', // Disable Apply until both dates are selected getIsDisabledCallback: ({ element }) => !element.selectedStartDate || !element.selectedEndDate } ];

AB09 · Dynamic Button Text (getTextCallback)

Change button text dynamically based on picker state.

Apply button shows day count, Clear shows what will be cleared
const picker = document.querySelector('#text-picker'); picker.actionButtons = [ { action: 'today', text: 'Today' }, { action: 'clear', text: 'Clear', // Show what will be cleared getTextCallback: ({ element }) => { if (!element.selectedStartDate) return 'Clear'; return 'Clear Selection'; } }, { action: 'apply', text: 'Apply', // Show day count when range is selected getTextCallback: ({ element }) => { if (!element.selectedStartDate || !element.selectedEndDate) return 'Apply'; const days = Math.floor((element.selectedEndDate - element.selectedStartDate) / (1000*60*60*24)) + 1; return `Apply (${days} day${days !== 1 ? 's' : ''})`; } } ];

AB10 · Dynamic CSS Classes (getClassCallback)

Apply dynamic CSS classes to buttons based on picker state. Callback can return a single string or array of strings.

Apply button changes color based on completion, Clear button becomes red when selection exists
// Define action buttons with dynamic classes const picker = document.querySelector('#css-picker'); picker.actionButtons = [ { action: 'today', text: 'Today' }, { action: 'clear', text: 'Clear', cssClass: 'clear-button', // Return array of classes getClassCallback: ({ element }) => { const classes = ['clear-button']; if (element.selectedStartDate || element.selectedEndDate) { classes.push('danger'); } return classes; } }, { action: 'apply', text: 'Apply', // Return single string based on validation getClassCallback: ({ element }) => { const hasComplete = element.selectedStartDate && element.selectedEndDate; return hasComplete ? 'apply-ready' : 'apply-waiting'; } } ]; // Inject custom styles into Shadow DOM picker.getCustomStylesCallback = () => ` .apply-ready { background: #10b981 !important; color: white !important; font-weight: 600 !important; } .apply-waiting { background: #d1d5db !important; color: #6b7280 !important; } .danger { background: #ef4444 !important; color: white !important; } `;

AB11 · Dynamic Tooltips (getTooltipCallback)

Show contextual tooltips that change based on picker state. Hover over buttons to see dynamic tooltips.

Tooltips update based on selection state and provide helpful context
const picker = document.querySelector('#tooltip-picker'); picker.actionButtons = [ { action: 'today', text: 'Today', tooltip: 'Jump to today', // Dynamic tooltip shows actual date getTooltipCallback: ({ element }) => { const today = new Date(); return `Set to ${today.toLocaleDateString()}`; } }, { action: 'clear', text: 'Clear', tooltip: 'Clear selection', // Show different message when nothing to clear getTooltipCallback: ({ element }) => { if (!element.selectedStartDate && !element.selectedEndDate) { return 'No selection to clear'; } return 'Clear the current date range'; } }, { action: 'apply', text: 'Apply', // Show validation help or day count getTooltipCallback: ({ element }) => { if (!element.selectedStartDate || !element.selectedEndDate) { return 'Select both start and end dates'; } const days = Math.floor((element.selectedEndDate - element.selectedStartDate) / (1000*60*60*24)) + 1; return `Apply ${days}-day range`; } } ];

AB12 · Combined Features & Priority System

Demonstrates callback priority: *Callback functions override static properties when both are present.

Priority Chain:
• Visibility: getIsVisibleCallback → isVisible → true
• Disabled: getIsDisabledCallback → isDisabled → false
• Text: getTextCallback → text → action
• Class: getClassCallback → cssClass → ''
• Tooltip: getTooltipCallback → tooltip → ''
Clear button uses all callbacks simultaneously, demonstrating callback priority
const picker = document.querySelector('#priority-picker'); picker.actionButtons = [ { action: 'today', text: 'Today' }, { action: 'clear', text: 'Clear All', // Overridden by getTextCallback cssClass: 'base-clear', // Overridden by getClassCallback tooltip: 'Static tooltip', // Overridden by getTooltipCallback isVisible: true, // Overridden by getIsVisibleCallback isDisabled: false, // Overridden by getIsDisabledCallback // Callbacks take priority over static properties getIsVisibleCallback: ({ element }) => element.selectedStartDate || element.selectedEndDate, getIsDisabledCallback: ({ element }) => !element.selectedStartDate && !element.selectedEndDate, getTextCallback: ({ element }) => { const hasSelection = element.selectedStartDate || element.selectedEndDate; return hasSelection ? 'Clear Selection' : 'Clear All'; }, getClassCallback: ({ element }) => (element.selectedStartDate || element.selectedEndDate) ? 'danger' : 'base-clear', getTooltipCallback: ({ element }) => { if (!element.selectedStartDate && !element.selectedEndDate) { return 'Nothing to clear'; } return 'Remove current selection'; } } ];

AB14 · Icons in Buttons (Font Awesome)

Button text is plain text (it is never parsed as HTML), so icon-font icons come from CSS: give the button a class with cssClass and draw the glyph in a ::before pseudo-element. Works with Font Awesome or any icon font. For a plain glyph or emoji, set icon: '★' instead — it renders as .drp__button-icon before the label.

Note: The calendar lives in Shadow DOM, so the icon rules go in through getCustomStylesCallback (or the custom-styles attribute). Load the icon font's stylesheet in the page <head> too: @font-face rules only take effect at document level.
Visual enhancement using Font Awesome icons
// Font Awesome is loaded in the page <head> (the @font-face must be document-level) const picker = document.querySelector('#icon-picker'); picker.actionButtons = [ { action: 'today', text: 'Today', cssClass: 'icon-today', tooltip: 'Jump to today' }, { action: 'clear', text: 'Clear', cssClass: 'icon-clear danger-icon' }, { action: 'apply', text: 'Apply', cssClass: 'icon-apply success-icon' } ]; // Draw the glyphs inside the Shadow DOM picker.getCustomStylesCallback = () => ` .drp__button { display: inline-flex; align-items: center; gap: 0.375rem; } .icon-today::before, .icon-clear::before, .icon-apply::before { font-family: 'Font Awesome 6 Free'; font-weight: 900; } .icon-today::before { content: '\\f783'; } /* calendar-day */ .icon-clear::before { content: '\\f057'; } /* circle-xmark */ .icon-apply::before { content: '\\f058'; } /* circle-check */ .success-icon { background: #10b981 !important; color: white !important; } .danger-icon { background: #ef4444 !important; color: white !important; } `;

AB15 · Action Item API Reference

actionButtons takes an array of action items (DateRangePickerActionItem, the shared KeenMate ActionItem) or built-in name strings (['today', 'clear']). The render-time get*Callbacks receive the picker context ctx: controller (the picker facade, also el.controller), element (the <web-daterangepicker> host) and the presentation flags. onClick receives the action detail: the same context plus action, id, item, source, sourceEvent, triggerElement and dataset.

Core Properties

Property Type Description
action 'today' | 'now' | 'clear' | 'apply' A built-in button. Omit it for a custom button.
id string Identifies a custom button; reported as detail.id in the action event.
text string Button label, plain text. Built-ins default to the localized label.
onClick (detail) => void | Promise<void> Click handler, for custom and built-in buttons. Runs before the action event and the built-in behaviour; awaited.

Static Properties

Property Type Default Description
cssClass string '' CSS class name(s) to apply to button.
tooltip string '' Tooltip text shown on hover.
isVisible boolean true Whether button is visible.
isDisabled boolean false Whether button is disabled.
isDanger boolean false Destructive action; adds the drp__button--danger class.
isToggled boolean false Toggle state is on; adds drp__button--toggled and aria-pressed="true". Still clickable.

Dynamic Callbacks (Override Static Properties)

Property Type Description
getIsVisibleCallback (ctx) => boolean Dynamic visibility control based on picker state.
getIsDisabledCallback (ctx) => boolean Dynamic disabled state based on picker state.
getIsToggledCallback (ctx) => boolean Dynamic toggle state.
getTextCallback (ctx) => string Dynamic button text based on picker state.
getClassCallback (ctx) => string | string[] Dynamic CSS classes (single string or array).
getTooltipCallback (ctx) => string Dynamic tooltip text based on picker state.

Priority System

When both static properties and callbacks are defined, callbacks take priority:

// Callback priority chain: getIsVisibleCallback → isVisible → true getIsDisabledCallback → isDisabled → false getIsToggledCallback → isToggled → false getTextCallback → text → localized built-in label getClassCallback → cssClass → '' getTooltipCallback → tooltip → ''

Click Order

el.beforeActionCallback(detail) // return false to cancel everything below → item.onClick(detail) → 'action' event / el.onAction(detail) → built-in behaviour (today / now / clear / apply)

What callbacks can use

Method/Property Description
ctx.controller.getSelectedRange() / getSelectedDate() / getSelectedRanges() / getSelectedDates() Read the current selection (getSelectedRange() is null until both ends are picked).
ctx.controller.selectToday() / clearSelection() / apply() / close() Drive the picker.
ctx.controller.showMessage(text, { type, autoHideMs }) Show feedback in the calendar.
ctx.element.selectedRanges = [{ start, end }] Set the selection (also selectedDate, selectedDates, selectedDatetime).
ctx.element.selectedStartDate / selectedEndDate Read the range endpoints, including a half-picked range.

Usage Example - All Features

const picker = document.querySelector('web-daterangepicker'); picker.actionButtons = [{ id: 'confirm', text: 'Confirm', cssClass: 'base-apply', tooltip: 'Static tooltip', isVisible: true, isDisabled: false, // Callbacks override static properties getIsVisibleCallback: ({ element }) => !!element.selectedStartDate, getIsDisabledCallback: ({ controller }) => !controller.getSelectedRange(), getTextCallback: ({ controller }) => { const range = controller.getSelectedRange(); return range ? `Confirm (${calculateDays(range.start, range.end)} days)` : 'Confirm'; }, getClassCallback: ({ controller }) => ['base-apply', controller.getSelectedRange() ? 'ready' : 'waiting'], getTooltipCallback: ({ controller }) => controller.getSelectedRange() ? 'Confirm selection' : 'Select dates first', onClick: (detail) => { // detail: { action: 'custom', id: 'confirm', item, source, controller, element, ... } detail.controller.close(); } }];

AB16 · Device-Adaptive Toolbar (rich on desktop, subset on phone)

A real consumer often wants a rich action bar on desktop but only the essentials on a phone. Drive actionButtons from the same environment signal the calendar itself reacts to — re-exported from the component package, so it's one import and no direct @keenmate/web-components-core dependency:

import { observeViewport, classifyDevice } from '@keenmate/web-daterangepicker'; const desktopActions = [ /* Today, Yesterday, Last 7 Days, This/Last Month, This Quarter, Clear, Apply */ ]; const mobileActions = [ { action: 'today', text: 'Today' }, { action: 'clear', text: 'Clear' }, { action: 'apply', text: 'Apply' } ]; // classifyDevice is capability-first (a landscape phone still reads 'mobile'; // a shrunk desktop window stays 'desktop'). observeViewport fires immediately // then on throttled resize. Reassign only when the resolved set changes — // actionButtons is an update input, so identical re-assigns re-render needlessly. observeViewport((env) => { el.actionButtons = classifyDevice(env) === 'mobile' ? mobileActions : desktopActions; });
detecting…
Capability, not width. The phone subset is keyed off classifyDevice (coarse pointer + no hover, shorter side < 600px) — not a raw width breakpoint — so a wide landscape phone still gets the subset. Use env.viewportWidth only for genuine "does it fit one row" layout questions.

AB17 · The action Event, beforeActionCallback & Toggle Buttons

Every button click (built-ins too) fires the action event; detail.action is the built-in name or 'custom', detail.id names a custom button. beforeActionCallback can veto a click (return false). isToggled / getIsToggledCallback render a toggle (aria-pressed), isDanger marks a destructive button. A button inside showMessage() HTML with data-action="custom" data-id="…" fires the same event with source: 'message' and its other data-* in detail.dataset.

Toggle "Weekends", try "Clear" (asks for confirmation), then use "Ask" and click the button in the message
Click a button…
let weekendsOff = false; picker.actionButtons = [ 'today', { id: 'weekends', text: 'Weekends', getIsToggledCallback: () => !weekendsOff, onClick: ({ element }) => { weekendsOff = !weekendsOff; element.disabledWeekdays = weekendsOff ? [0, 6] : []; } }, { id: 'ask', text: 'Ask', onClick: ({ controller }) => controller.showMessage( 'Keep this range? <button data-action="custom" data-id="keep" data-answer="yes">Yes</button>', { type: 'info' }) }, { action: 'clear', isDanger: true } ]; // Runs before onClick / the action event / the built-in. false cancels. picker.beforeActionCallback = (detail) => { if (detail.action === 'clear' && !confirm('Clear the selection?')) return false; }; picker.addEventListener('action', (e) => { const { action, id, source, dataset } = e.detail; console.log(action, id, source, dataset); // e.g. 'custom' 'keep' 'message' { answer: 'yes' } if (id === 'keep') e.detail.controller.hideMessage(); });
