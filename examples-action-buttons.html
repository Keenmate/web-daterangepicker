AB03 · Commit Mode (when the pick commits & the calendar closes)

The commit-mode attribute governs how a selection is committed (written to the input, select / change fired). Closing is a separate axis: close-on-select, close-on-outside-click and close-on-scroll; Escape and close() always close, and closing discards a staged (not yet applied) pick.

Picks are only staged — nothing is written until the app calls commit() (here the custom "Done" button). No built-in Apply button; an outside click doesn't close (Escape does, discarding the staged pick)
Commits and closes when selection completes (click, drag-adjust). No Apply button. Multiple mode can't use this
Every completed pick is written immediately (select / change fire), but the calendar stays open so the guest can adjust the dates. Escape / outside click closes, keeping the value.
Shows an Apply button; the selection is staged until Apply is clicked, which commits and closes 
// Commit modes: 'selection' (default), 'apply', 'manual'
<web-daterangepicker commit-mode="selection"></web-daterangepicker>
<web-daterangepicker commit-mode="apply"></web-daterangepicker>
<web-daterangepicker commit-mode="manual"></web-daterangepicker>

AB09 · Dynamic Button Text (getTextCallback)

Change button text dynamically based on picker state.

Apply button shows day count, Clear shows what will be cleared 
const picker = document.querySelector('#text-picker');

picker.actionButtons = [
{ action: 'today', text: 'Today' },
{
  action: 'clear',
  text: 'Clear',
  // Show what will be cleared
  getTextCallback: ({ element }) => {
    if (!element.selectedStartDate) return 'Clear';
    return 'Clear Selection';
  }
},
{
  action: 'apply',
  text: 'Apply',
  // Show day count when range is selected
  getTextCallback: ({ element }) => {
    if (!element.selectedStartDate || !element.selectedEndDate) return 'Apply';
    const days = Math.floor((element.selectedEndDate - element.selectedStartDate) / (1000*60*60*24)) + 1;
    return `Apply (${days} day${days !== 1 ? 's' : ''})`;
  }
}
];

AB12 · Combined Features & Priority System

Demonstrates callback priority: *Callback functions override static properties when both are present.

Priority Chain:
• Visibility: getIsVisibleCallback → isVisible → true
• Disabled: getIsDisabledCallback → isDisabled → false
• Text: getTextCallback → text → localized built-in label
• Class: getClassCallback → cssClass → ''
• Tooltip: getTooltipCallback → tooltip → ''
Clear button uses all callbacks simultaneously, demonstrating callback priority 
const picker = document.querySelector('#priority-picker');

picker.actionButtons = [
{ action: 'today', text: 'Today' },
{
  action: 'clear',
  text: 'Clear All',           // Overridden by getTextCallback
  cssClass: 'base-clear',      // Overridden by getClassCallback
  tooltip: 'Static tooltip',  // Overridden by getTooltipCallback
  isVisible: true,            // Overridden by getIsVisibleCallback
  isDisabled: false,          // Overridden by getIsDisabledCallback

  // Callbacks take priority over static properties
  getIsVisibleCallback: ({ element }) =>
    element.selectedStartDate || element.selectedEndDate,
  getIsDisabledCallback: ({ element }) =>
    !element.selectedStartDate && !element.selectedEndDate,
  getTextCallback: ({ element }) => {
    const hasSelection = element.selectedStartDate || element.selectedEndDate;
    return hasSelection ? 'Clear Selection' : 'Clear All';
  },
  getClassCallback: ({ element }) =>
    (element.selectedStartDate || element.selectedEndDate) ? 'danger' : 'base-clear',
  getTooltipCallback: ({ element }) => {
    if (!element.selectedStartDate && !element.selectedEndDate) {
      return 'Nothing to clear';
    }
    return 'Remove current selection';
  }
}
];

AB14 · Icons in Buttons (Font Awesome)

AB15 · Action Item API Reference

actionButtons takes an array of action items (DateRangePickerActionItem, the shared Keenmate ActionItem) or built-in name strings (['today', 'clear']). The render-time get*Callbacks receive the picker context ctx: controller (the picker facade, also el.controller), element (the <web-daterangepicker> host) and the presentation flags. onClick receives the action detail: the same context plus action, id, item, source, sourceEvent, triggerElement and dataset.

Core Properties

Property Type Description
action 'today' | 'now' | 'clear' | 'apply' A built-in button. Omit it for a custom button.
id string Identifies a custom button; reported as detail.id in the action event.
text string Button label, plain text. Built-ins default to the localized label.
onClick (detail) => void | Promise<void> Click handler, for custom and built-in buttons. Runs before the built-in behaviour and the action event; awaited.

Static Properties

Property Type Default Description
cssClass string '' CSS class name(s) to apply to button.
icon string '' An icon before the label (core renderIcon): markup (<svg…>) is inserted as-is, an ASCII name (gear) is masked from the page's --base-icon-gear token in currentColor, anything else (an emoji) shows as text. An icon-only button takes its accessible name from tooltip.
tooltip string '' Tooltip text shown on hover.
isVisible boolean true Whether button is visible.
isDisabled boolean false Whether button is disabled.
isDanger boolean false Destructive action; adds the drp__button--danger class.
isToggled boolean false Toggle state is on; adds drp__button--toggled and aria-pressed="true". Still clickable.

Dynamic Callbacks (Override Static Properties)

Property Type Description
getIsVisibleCallback (ctx) => boolean Dynamic visibility control based on picker state.
getIsDisabledCallback (ctx) => boolean Dynamic disabled state based on picker state.
getIsToggledCallback (ctx) => boolean Dynamic toggle state.
getTextCallback (ctx) => string Dynamic button text based on picker state.
getIconCallback (ctx) => string Dynamic icon glyph based on picker state.
getClassCallback (ctx) => string | string[] Dynamic CSS classes (single string or array).
getTooltipCallback (ctx) => string Dynamic tooltip text based on picker state.

Priority System

When both static properties and callbacks are defined, callbacks take priority:

// Callback priority chain:
getIsVisibleCallback → isVisible → true
getIsDisabledCallback → isDisabled → false
getIsToggledCallback → isToggled → false
getTextCallback → text → localized built-in label
getIconCallback → icon → ''
getClassCallback → cssClass → ''
getTooltipCallback → tooltip → ''

Click Order

el.beforeActionCallback(detail)  // return false to cancel everything below
→ item.onClick(detail)
→ built-in behaviour (today / now / clear / apply)
→ 'action' event / el.onAction(detail)

What callbacks can use

Method/Property Description
ctx.controller.selectedDate / selectedRanges / selectedDates / selectedStartDate / selectedEndDate Read the current selection (selectedRanges is empty until both ends are picked; read-only properties).
ctx.controller.selectToday() / clearSelection() / commit() / close() Drive the picker.
ctx.controller.showMessage(text, { variant, autoHideMs }) Show feedback in the calendar.
ctx.element.selectedRanges = [{ start, end }] Set the selection (also selectedDate, selectedDates, selectedDatetime).
ctx.element.selectedStartDate / selectedEndDate Read the range endpoints, including a half-picked range.

Usage Example - All Features

const picker = document.querySelector('web-daterangepicker');

picker.actionButtons = [{
id: 'confirm',
text: 'Confirm',
cssClass: 'base-apply',
tooltip: 'Static tooltip',
isVisible: true,
isDisabled: false,

// Callbacks override static properties
getIsVisibleCallback: ({ element }) => !!element.selectedStartDate,
getIsDisabledCallback: ({ controller }) => !controller.selectedRanges[0],
getTextCallback: ({ controller }) => {
  const range = controller.selectedRanges[0];
  return range ? `Confirm (${calculateDays(range.start, range.end)} days)` : 'Confirm';
},
getClassCallback: ({ controller }) => ['base-apply', controller.selectedRanges[0] ? 'ready' : 'waiting'],
getTooltipCallback: ({ controller }) =>
  controller.selectedRanges[0] ? 'Confirm selection' : 'Select dates first',

onClick: (detail) => {

AB16 · Device-Adaptive Toolbar (rich on desktop, subset on phone)

A real consumer often wants a rich action bar on desktop but only the essentials on a phone. Drive actionButtons from the same environment signal the calendar itself reacts to — re-exported from the component package, so it's one import and no direct @keenmate/web-components-core dependency: 

import { observeViewport, classifyDevice } from '@keenmate/web-daterangepicker';

const desktopActions = [ /* Today, Yesterday, Last 7 Days, This/Last Month, This Quarter, Clear, Apply */ ];
const mobileActions  = [ { action: 'today', text: 'Today' }, { action: 'clear', text: 'Clear' }, { action: 'apply', text: 'Apply' } ];

// classifyDevice is capability-first (a landscape phone still reads 'mobile';
// a shrunk desktop window stays 'desktop'). observeViewport fires immediately
// then on throttled resize. Reassign only when the resolved set changes —
// actionButtons is an update input, so identical re-assigns re-render needlessly.
observeViewport((env) => {
el.actionButtons = classifyDevice(env) === 'mobile' ? mobileActions : desktopActions;
});
detecting…
Capability, not width. The phone subset is keyed off classifyDevice (coarse pointer + no hover, shorter side < 600px) — not a raw width breakpoint — so a wide landscape phone still gets the subset. Use env.viewportWidth only for genuine "does it fit one row" layout questions.

AB17 · The action Event, beforeActionCallback & Toggle Buttons

Every button click (built-ins too) fires the action event; detail.action is the built-in name or 'custom', detail.id names a custom button. beforeActionCallback can veto a click (return false). isToggled / getIsToggledCallback render a toggle (aria-pressed), isDanger marks a destructive button. A button inside showMessage() HTML with data-action="custom" data-id="…" fires the same event with source: 'message' and its other data-* in detail.dataset.

Toggle "Weekends", try "Clear" (asks for confirmation), then use "Ask" and click the button in the message
Click a button…
let weekendsOff = false;

picker.actionButtons = [
'today',
{ id: 'weekends', text: 'Weekends',
  getIsToggledCallback: () => !weekendsOff,
  onClick: ({ element }) => {
    weekendsOff = !weekendsOff;
    element.disabledWeekdays = weekendsOff ? [0, 6] : [];
  } },
{ id: 'ask', text: 'Ask',
  onClick: ({ controller }) => controller.showMessage(
    'Keep this range? <button data-action="custom" data-id="keep" data-answer="yes">Yes</button>',
    { type: 'info' }) },
{ action: 'clear', isDanger: true }
];

// Runs before onClick / the built-in / the action event. false cancels.
picker.beforeActionCallback = (detail) => {
if (detail.action === 'clear' && !confirm('Clear the selection?')) return false;
};

picker.addEventListener('action', (e) => {
const { action, id, source, dataset } = e.detail;
console.log(action, id, source, dataset); // e.g. 'custom' 'keep' 'message' { answer: 'yes' }
if (id === 'keep') e.detail.controller.hideMessage();
});
