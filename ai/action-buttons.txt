ACTION BUTTONS
==============

CRITICAL: JavaScript API ONLY
Action buttons configuration not available as web component attributes.
Action buttons are web-components-core ActionItems (type: DateRangePickerActionItem).

BUILT-IN BUTTONS
----------------
Built-in actions: 'today', 'now' (time/datetime), 'clear', 'apply'.
Defaults depend on the mode (Today + Clear; Now in time/datetime; Apply when
commit-mode="apply").

Control visibility of the defaults:

<!-- Web Component -->
<web-daterangepicker
  selection-mode="range"
  show-today-button="true"
  show-clear-button="true">
</web-daterangepicker>

The Apply button is not toggled directly. It is rendered when
commit-mode="apply" (see below) and omitted for 'selection' and 'manual'.

COMMIT-MODE CONTROL (commit) + CLOSE OPTIONS (close)
----------------------------------------------------
Two separate axes. commit-mode = when a pick is COMMITTED (written to the
input, change fired):

<!-- Web Component -->
<web-daterangepicker
  commit-mode="selection">  <!-- 'selection', 'apply', 'manual' -->
</web-daterangepicker>

Modes:
- 'selection' - Every completed pick (single click, range completion,
                drag-adjust) is written immediately. No Apply button.
                Default for date mode. (Not available in 'multiple' mode.)
- 'apply'     - Render an Apply button; picks are staged until Apply is
                clicked, which commits and closes. Default for time/datetime
                and for 'multiple' selection mode.
- 'manual'    - Picks are only STAGED; nothing is written until the app calls
                commit() (e.g. onClick: (d) => d.controller.commit()). No built-in
                Apply button.

Close options:
- close-on-select        default true; closes when a pick completes
                                (commit-mode="selection" only)
- close-on-outside-click default true; false when commit-mode="manual"
                                unless set explicitly
- close-on-scroll        default true (floating)
Escape and close() always close. Closing without commit() discards a staged pick.

booking.com flow (written immediately, calendar stays open to adjust):
<web-daterangepicker selection-mode="range"
  commit-mode="selection" close-on-select="false"></web-daterangepicker>

CUSTOM ACTION BUTTONS
---------------------
CRITICAL: JavaScript API ONLY (actionButtons property)

const el = document.querySelector('web-daterangepicker');

el.actionButtons = [
  'today',                                   // string shorthand for a built-in
  { action: 'clear', text: 'Reset' },        // built-in with overrides
  { id: 'last-week', text: 'Last Week', onClick: (d) => { ... } }  // custom: id, NO action
];

A custom button sets `id` (and no `action`). `action` is only for the
built-ins: 'today' | 'now' | 'clear' | 'apply'.

DateRangePickerActionItem INTERFACE
-----------------------------------
{
  action?: 'today' | 'now' | 'clear' | 'apply';  // built-ins only
  id?: string;                // identifies a custom button (reported in the action event)
  text?: string;              // plain text (NOT HTML); built-ins default to the locale label

  // Static properties
  icon?: string;              // core ActionItem field (see ICONS below)
  tooltip?: string;
  cssClass?: string;
  isVisible?: boolean;        // Default: true
  isDisabled?: boolean;       // Default: false
  isDanger?: boolean;         // destructive styling (.drp__button--danger)
  isToggled?: boolean;        // toggle state: .drp__button--toggled + aria-pressed="true"

  // Render-time callbacks - receive the PICKER CONTEXT (ctx), win over static
  getTextCallback?: (ctx) => string;
  getIconCallback?: (ctx) => string;
  getTooltipCallback?: (ctx) => string;
  getClassCallback?: (ctx) => string | string[];
  getIsVisibleCallback?: (ctx) => boolean;
  getIsDisabledCallback?: (ctx) => boolean;
  getIsToggledCallback?: (ctx) => boolean;

  // Click handler - receives the ACTION DETAIL (works for built-ins too)
  onClick?: (detail) => void | Promise<void>;
}

THE PICKER CONTEXT (render-time callbacks)
------------------------------------------
ctx.controller   - public facade (same object as el.controller):
                   selectedDate, selectedDates, selectedRanges,
                   selectedStartDate, selectedEndDate, selectedTime,
                   selectedDatetime, isOpen (all read-only),
                   selectToday(), selectNow(), clearSelection(), commit(),
                   open(), close(), toggle(), setPresentation(p),
                   prevMonth(i?), nextMonth(i?), lock(a?), unlock(a?),
                   showMessage(content, { type, autoHideMs }), hideMessage(),
                   showSummary(html), hideSummary(), showLoader(t?), hideLoader(t?)
ctx.element      - the <web-daterangepicker> host (selectedStartDate,
                   selectedEndDate, selectedRanges = [...], etc.)
ctx.presentation + presentation flags of the open chrome

There is NO ctx.picker (the raw engine is not part of the public API), and
render-time callbacks get no `action` / `button` fields.

THE ACTION DETAIL (onClick / beforeActionCallback / action event)
-----------------------------------------------------------------
The picker context PLUS:
  action          - built-in name, or 'custom'
  id              - the item's id
  item            - the clicked item
  source          - 'action-buttons' | 'message' | 'summary' | 'calendar'
  sourceEvent     - the DOM event (click / keydown)
  triggerElement  - the activated element
  dataset         - the trigger's other data-* attributes

CLICK ORDER
-----------
beforeActionCallback(detail) -> item.onClick(detail) -> 'action' event (onAction)
-> built-in behaviour (today/now/clear/apply).

el.beforeActionCallback = async (d) => {
  if (d.action === 'clear' && !confirm('Clear the selection?')) return false; // cancels everything
};

`false` cancels: no onClick, no action event, no built-in. May be async (the
button is busy meanwhile).

el.addEventListener('action', (e) => {
  if (e.detail.id === 'last-week') analytics.track('preset', e.detail.id);
});
// or the twin (receives the DETAIL, not the event):
el.onAction = (d) => console.log(d.action, d.id, d.source);

CALLBACK PRIORITY
-----------------
get*Callback -> static property -> built-in default:
- getIsVisibleCallback -> isVisible -> true
- getIsDisabledCallback -> isDisabled -> false
- getIsToggledCallback -> isToggled -> false
- getTextCallback -> text -> built-in locale label
- getClassCallback -> cssClass -> ''
- getTooltipCallback -> tooltip -> none

PRESET BUTTONS
--------------
Quick date range shortcuts:

const el = document.querySelector('#picker');

el.actionButtons = [
  {
    id: 'last-week',
    text: 'Last Week',
    onClick: ({ element }) => {
      const end = new Date();
      const start = new Date();
      start.setDate(end.getDate() - 7);
      element.selectedRanges = [{ start, end }];
    }
  },
  {
    id: 'next-month',
    text: 'Next Month',
    onClick: ({ element }) => {
      const start = new Date();
      const end = new Date();
      end.setMonth(end.getMonth() + 1);
      element.selectedRanges = [{ start, end }];
    }
  },
  'clear',
  'apply'
];

CONDITIONAL VISIBILITY
----------------------
Show/hide buttons based on state:

el.actionButtons = [
  'today',
  'clear',
  {
    action: 'apply',
    // Only show when both dates selected
    getIsVisibleCallback: (ctx) => !!ctx.controller.selectedRanges[0]
  }
];

DYNAMIC DISABLED STATE
----------------------
el.actionButtons = [
  'today',
  {
    action: 'clear',
    // Disable when nothing selected
    getIsDisabledCallback: ({ element }) =>
      !element.selectedStartDate && !element.selectedEndDate
  },
  {
    action: 'apply',
    // Disable until both dates selected
    getIsDisabledCallback: (ctx) => !ctx.controller.selectedRanges[0]
  }
];

DYNAMIC TEXT
------------
el.actionButtons = [
  {
    action: 'apply',
    getTextCallback: (ctx) => {
      const range = ctx.controller.selectedRanges[0];
      if (!range) return 'Apply';
      const days = Math.floor((range.end - range.start) / 864e5) + 1;
      return `Apply (${days} day${days !== 1 ? 's' : ''})`;
    }
  }
];

DYNAMIC CSS CLASSES
-------------------
el.actionButtons = [
  {
    action: 'clear',
    cssClass: 'clear-button',
    // Return array of classes
    getClassCallback: ({ element }) => {
      const classes = ['clear-button'];
      if (element.selectedStartDate || element.selectedEndDate) classes.push('danger');
      return classes;
    }
  },
  {
    action: 'apply',
    // Return single string
    getClassCallback: (ctx) =>
      ctx.controller.selectedRanges[0] ? 'apply-ready' : 'apply-waiting'
  }
];

// Inject styles into the shadow root
el.getCustomStylesCallback = () => `
  .apply-ready   { background: #10b981 !important; color: white !important; font-weight: 600 !important; }
  .apply-waiting { background: #d1d5db !important; color: #6b7280 !important; }
  .danger        { background: #ef4444 !important; color: white !important; }
`;

For destructive styling prefer `isDanger: true` (adds .drp__button--danger).

TOGGLE BUTTONS (isToggled)
-------------------------
el.actionButtons = [
  {
    id: 'weekends',
    text: 'Weekends',
    getIsToggledCallback: () => showWeekends,   // .drp__button--toggled + aria-pressed
    onClick: () => { showWeekends = !showWeekends; /* re-render via reassigning */ }
  }
];

DYNAMIC TOOLTIPS
----------------
el.actionButtons = [
  {
    action: 'today',
    getTooltipCallback: () => `Set to ${new Date().toLocaleDateString()}`
  },
  {
    action: 'clear',
    getTooltipCallback: ({ element }) =>
      (!element.selectedStartDate && !element.selectedEndDate)
        ? 'No selection to clear'
        : 'Clear the current date range'
  },
  {
    action: 'apply',
    getTooltipCallback: (ctx) => {
      const range = ctx.controller.selectedRanges[0];
      if (!range) return 'Select both start and end dates';
      const days = Math.floor((range.end - range.start) / 864e5) + 1;
      return `Apply ${days}-day range`;
    }
  }
];

Each button keeps its own tooltip (several custom buttons no longer share the
first one's tooltip).

ICONS IN BUTTONS
----------------
`text` is set as PLAIN TEXT - HTML in `text` is no longer injected. `icon` /
`getIconCallback` are part of the core ActionItem shape. For icon glyphs on the
footer buttons, style a cssClass:

el.actionButtons = [
  { action: 'today', text: 'Today', cssClass: 'with-icon icon-today', tooltip: 'Jump to today' },
  { action: 'clear', text: 'Clear', isDanger: true }
];

el.getCustomStylesCallback = () => `
  .with-icon { display: inline-flex; align-items: center; gap: 0.375rem; }
  .icon-today::before { content: '\\1F4C5'; }
`;

BUSINESS PERIOD PRESETS
-----------------------
const setRange = (element, start, end) => { element.selectedRanges = [{ start, end }]; };

el.actionButtons = [
  {
    id: 'last-business-week',
    text: 'Last Business Week',
    tooltip: 'Monday-Friday of last week',
    onClick: ({ element }) => {
      const today = new Date();
      const dayOfWeek = today.getDay();
      const daysToLastMonday = dayOfWeek === 0 ? 6 : dayOfWeek + 6;
      const lastMonday = new Date(today);
      lastMonday.setDate(today.getDate() - daysToLastMonday);
      const lastFriday = new Date(lastMonday);
      lastFriday.setDate(lastMonday.getDate() + 4);
      setRange(element, lastMonday, lastFriday);
    }
  },
  {
    id: 'this-quarter',
    text: 'This Quarter',
    tooltip: 'Current fiscal quarter',
    onClick: ({ element }) => {
      const now = new Date();
      const q = Math.floor(now.getMonth() / 3);
      setRange(element, new Date(now.getFullYear(), q * 3, 1), new Date(now.getFullYear(), q * 3 + 3, 0));
    }
  },
  {
    id: 'ytd',
    text: 'Year to Date',
    tooltip: 'From Jan 1 to today',
    onClick: ({ element }) => {
      const today = new Date();
      setRange(element, new Date(today.getFullYear(), 0, 1), today);
    }
  },
  {
    id: 'rolling-90',
    text: 'Rolling 90 Days',
    cssClass: 'rolling-period',
    onClick: ({ element }) => {
      const end = new Date();
      const start = new Date();
      start.setDate(end.getDate() - 89);
      setRange(element, start, end);
    }
  },
  'clear',
  'apply'
];

COMBINING ALL FEATURES
----------------------
const hasSelection = ({ element }) => !!(element.selectedStartDate || element.selectedEndDate);

el.actionButtons = [
  'today',
  {
    action: 'clear',
    text: 'Clear All',               // Overridden by getTextCallback
    cssClass: 'base-clear',          // Overridden by getClassCallback
    tooltip: 'Static tooltip',       // Overridden by getTooltipCallback
    isVisible: true,                 // Overridden by getIsVisibleCallback
    isDisabled: false,               // Overridden by getIsDisabledCallback

    getIsVisibleCallback: hasSelection,
    getIsDisabledCallback: (ctx) => !hasSelection(ctx),
    getTextCallback: (ctx) => hasSelection(ctx) ? 'Clear Selection' : 'Clear All',
    getClassCallback: (ctx) => hasSelection(ctx) ? 'danger' : 'base-clear',
    getTooltipCallback: (ctx) => hasSelection(ctx) ? 'Remove current selection' : 'Nothing to clear',

    // Runs for built-ins too, BEFORE the built-in clear
    onClick: (d) => console.log('clearing', d.controller.selectedRanges[0])
  }
];

WHAT onClick CAN USE
--------------------
onClick: (d) => {
  // Which button
  d.action;  d.id;  d.source;  d.dataset;

  // Read state via the controller facade
  const range = d.controller.selectedRanges[0];
  const date  = d.controller.selectedDate;
  const open  = d.controller.isOpen;

  // Drive the picker
  d.controller.clearSelection();
  d.controller.commit();
  d.controller.close();
  d.controller.showMessage('Saved', { type: 'success', autoHideMs: 2000 });

  // Or the host element (full element API)
  d.element.selectedRanges = [{ start, end }];
  const mode = d.element.getAttribute('selection-mode');
}

BUTTON ORDER
------------
Buttons appear in array order:

el.actionButtons = [
  'today',                                       // Left
  { id: 'preset', text: 'Preset', onClick: ... },
  'clear',
  'apply'                                        // Right
];

UPDATING BUTTONS
----------------
// Replace all buttons
el.actionButtons = newButtonsArray;

// Add button
el.actionButtons = [
  ...el.actionButtons,
  { id: 'new', text: 'New', onClick: handler }
];

// Remove button
el.actionButtons = el.actionButtons.filter(btn => (btn.action ?? btn) !== 'clear');

// Calendar auto-updates

DEBUGGING
---------
el.actionButtons = [
  {
    id: 'debug',
    text: 'Debug',
    onClick: (d) => {
      console.log('Picker state:', {
        range: d.controller.selectedRanges[0],
        isOpen: d.controller.isOpen
      });
    }
  }
];

// Or log every activation (built-ins, custom, data-action triggers)
el.onAction = (d) => console.log('action', d.action, d.id, d.source);

HTML TRIGGERS (data-action)
---------------------------
Buttons inside showMessage / summary / custom-rendered HTML fire the same
pipeline. Custom triggers need data-id; other data-* go to detail.dataset:

el.controller.showMessage(
  'Unsaved changes. <button data-action="custom" data-id="discard" data-reason="user">Discard</button>',
  { type: 'warning' }
);
el.addEventListener('action', (e) => {
  if (e.detail.id === 'discard') {      // e.detail.source === 'message'
    console.log(e.detail.dataset.reason); // 'user'
  }
});

`data-action` may also name a built-in: <button data-action="today">Today</button>.

BEST PRACTICES
--------------
1. Built-ins via `action` or the string shorthand; custom buttons via `id`.
2. Read state with ctx.controller (or ctx.element) - never an engine instance.
3. Keep onClick handlers simple; setting element.selectedRanges re-renders.
4. Style with cssClass / getClassCallback / isDanger; inject CSS via
   getCustomStylesCallback.
5. Use beforeActionCallback to confirm/cancel, the `action` event for
   cross-cutting tracking.

ACCESSIBILITY
-------------
el.actionButtons = [{
  action: 'apply',
  text: 'Apply Selection',
  getTooltipCallback: (ctx) => ctx.controller.selectedRanges[0]
    ? 'Confirm and close calendar'
    : 'Please select both start and end dates'
}];

Toggle buttons (isToggled / getIsToggledCallback) render aria-pressed="true".

COMMON PATTERNS
---------------
Minimal buttons:
el.actionButtons = ['apply'];

Maximum buttons (all presets):
el.actionButtons = [
  'today',
  { id: 'yesterday',   text: 'Yesterday',    onClick: setYesterday },
  { id: 'last-7',      text: 'Last 7 Days',  onClick: setLastWeek },
  { id: 'last-30',     text: 'Last 30 Days', onClick: setLastMonth },
  'clear',
  'apply'
];

Context-aware buttons:
el.actionButtons = [{
  action: 'apply',
  getIsVisibleCallback: (ctx) => !!ctx.controller.selectedRanges[0],
  getTextCallback: (ctx) => {
    const r = ctx.controller.selectedRanges[0];
    return r ? `Apply (${Math.floor((r.end - r.start) / 864e5) + 1} days)` : 'Apply';
  }
}];

WEB COMPONENT LIMITATIONS
--------------------------
actionButtons is a PROPERTY only.

✅ Works (set as property):
const el = document.querySelector('web-daterangepicker');
el.actionButtons = [...];

❌ Doesn't work (attribute):
<web-daterangepicker
  action-buttons="...">  <!-- Not an attribute -->
</web-daterangepicker>
