EVENTS & CALLBACKS
==================

EVENT SYSTEM
------------
The element fires CustomEvents (bubbling, composed: false — listen on the
element or any ancestor in the same tree):

  select        - a date/range/time was selected (or applied)
  change        - fires right after `select`, SAME detail (form-style wiring)
  action        - an action button or a data-action trigger was activated
  month-change  - the visible month(s) changed (any navigation)
  ready         - first build done (once per element lifetime)

Every detail carries `controller` (the public facade, same as el.controller)
and `element` (the host) as NON-enumerable properties — JSON.stringify(detail)
and LiveView pushEvent see only the data — plus the presentation flags.

ON* TWINS (receive the DETAIL, not the event)
---------------------------------------------
el.onSelect      = (detail) => ...
el.onChange      = (detail) => ...
el.onAction      = (detail) => ...
el.onMonthChange = (detail) => ...
el.onReady       = (detail) => ...

el.onSelect = (d) => console.log(d.date);   // NOT d.detail / e.detail

LISTENING TO EVENTS
-------------------
const el = document.querySelector('web-daterangepicker');

el.addEventListener('select', (event) => {
  console.log('Selected:', event.detail);
});

// Or 'change' (fires right after select)
el.addEventListener('change', (event) => {
  console.log('Changed:', event.detail);
});

SINGLE MODE EVENT DATA (SelectEventDetail)
------------------------------------------
{
  date: Date object,
  formattedValue: "2025-11-17",
  controller, element            // non-enumerable
}

el.addEventListener('select', (event) => {
  const { date, formattedValue } = event.detail;
  console.log('Date object:', date);
  console.log('Formatted:', formattedValue);
  console.log('Day of week:', date.getDay());
});

RANGE MODE EVENT DATA
---------------------
{
  dateRange: { start: Date, end: Date },
  formattedValue: "2025-11-17 - 2025-11-24"
}

el.onSelect = ({ dateRange, formattedValue }) => {
  const nights = Math.floor((dateRange.end - dateRange.start) / 864e5);
  console.log(formattedValue, 'Nights:', nights);
};

RANGE WITH DISABLED DATES HANDLING
-----------------------------------
Mode: 'allow'
{
  dateRange: { start, end },
  formattedValue: "...",
  enabledDates: [Date, ...],           // Enabled dates in range
  disabledDates: [Date, ...],          // Disabled dates in range
  getEnabledDateCount: () => number,
  getTotalDays: () => number
}

Mode: 'split'
{
  dateRanges: [{ start, end }, { start, end }],
  dates: [Date, ...],                  // All enabled dates
  formattedValue: "..."
}

Mode: 'individual'
{
  dates: [Date, ...],                  // All enabled dates
  formattedValue: "..."
}

el.addEventListener('select', (event) => {
  const { dateRange, enabledDates, disabledDates } = event.detail;
  console.log('Total:', event.detail.getTotalDays(), 'days');
});

MULTIPLE MODE EVENT DATA
------------------------
{
  dates: [Date, ...],                  // Selected individual dates
  dateRanges: [{ start, end }, ...],   // Selected ranges
  formattedValue: "..."
}

MONTH-CHANGE EVENT
------------------
Fires after any navigation (arrows, keyboard, rolling selector, programmatic).

el.addEventListener('month-change', (e) => {
  const { monthIndex, year, month, visibleMonths } = e.detail;
  // month is 0-11; visibleMonths: [{ year, month }, ...]
});
el.onMonthChange = (d) => console.log(d.year, d.month + 1);

READY EVENT
-----------
el.addEventListener('ready', (e) => {
  const { controller, element } = e.detail;
});

ACTION EVENT
------------
Fires for EVERY action button (built-ins too) and every HTML data-action
trigger (e.g. buttons in showMessage HTML).

detail:
  action          - 'today' | 'now' | 'clear' | 'apply' | 'custom'
  id              - the custom item's id / the trigger's data-id
  item            - the clicked item (synthetic for HTML triggers)
  source          - 'action-buttons' | 'message' | 'summary' | 'calendar'
  sourceEvent     - the DOM event
  triggerElement  - the activated element
  dataset         - the trigger's other data-* (minus data-action / data-id),
                    camelCased: data-start-date -> dataset.startDate
  controller, element, presentation flags

Order: beforeActionCallback -> item.onClick -> action event (onAction) -> built-in.

el.addEventListener('action', (e) => {
  console.log(e.detail.action, e.detail.id, e.detail.source, e.detail.dataset);
});

USE IN MESSAGE BUTTONS
----------------------
Custom HTML triggers need data-action="custom" AND data-id:

el.controller.showMessage(`
  <button data-action="custom" data-id="alt-dates"
          data-start-date="2026-01-14"
          data-end-date="2026-01-17"
          data-nights="3">
    Jan 14 - Jan 17 (3 nights)
  </button>
`, { type: 'info' });

el.addEventListener('action', (e) => {
  if (e.detail.id !== 'alt-dates') return;       // e.detail.source === 'message'
  const { startDate, endDate } = e.detail.dataset;
  el.selectedRanges = [{ start: new Date(startDate), end: new Date(endDate) }];
  el.controller.hideMessage();
});

USE IN ACTION BUTTONS
---------------------
el.actionButtons = [
  { id: 'last-7', text: 'Last 7 Days', onClick: (d) => { /* per-button logic */ } }
];

// Or handle all actions in one place:
el.addEventListener('action', (e) => {
  if (e.detail.id === 'last-7') { ... }
});

BEFOREACTIONCALLBACK
--------------------
el.beforeActionCallback = async (d) => {
  if (d.action === 'clear' && !(await confirmDialog())) return false;
};
`false` cancels entirely (no onClick, no action event, no built-in). May be
async; the button is busy meanwhile.

EXAMPLE: AVAILABILITY ALTERNATIVES
----------------------------------
el.beforeSelectCallback = async (ctx) => {
  const result = await checkAvailability(ctx.range);
  if (!result.available) {
    ctx.markRangeInvalid();                 // keep the rejected range visible
    ctx.controller.showMessage(`
      <div>Dates not available. Try these:</div>
      ${result.alternatives.map(alt => `
        <button data-action="custom" data-id="alternative"
                data-start-date="${alt.start}"
                data-end-date="${alt.end}">
          ${alt.label}
        </button>
      `).join('')}
    `, { type: 'warning' });
    return false;
  }
};

el.addEventListener('action', (e) => {
  if (e.detail.id !== 'alternative') return;
  const { startDate, endDate } = e.detail.dataset;
  el.selectedRanges = [{ start: new Date(startDate), end: new Date(endDate) }];
  el.controller.hideMessage();
});

BEFORESELECTCALLBACK
--------------------
CRITICAL: property only (not an attribute).
Validation/control BEFORE a selection is finalized.

el.beforeSelectCallback = (ctx) => { ... };

CONTEXT (BeforeSelectContext)
  mode            - 'single' | 'range' | 'multiple'
  date            - proposed date (single mode)
  range           - proposed { start, end } (range mode)
  subRanges       - split/individual handling: enabled-only segments
  enabledDates    - split/individual handling: enabled dates in the envelope
  markRangeInvalid() - range mode: keep a rejected range visible with error styling
  controller, element, presentation flags

RETURN CONTRACT
  nothing (undefined) - accept as-is
  false               - reject; previous selection restored
  Date                - accept this adjusted date (single)
  DateRange           - accept this adjusted range (range)
  DateRange[]         - replace with these N independent ranges
  null                - clear the selection entirely

Messages: ctx.controller.showMessage(text, { type: 'error' | 'warning' | 'info' | 'success', autoHideMs })

SINGLE MODE VALIDATION
----------------------
Block weekends:

el.beforeSelectCallback = (ctx) => {
  const day = ctx.date.getDay();
  if (day === 0 || day === 6) {
    ctx.controller.showMessage('Weekends not allowed', { type: 'error' });
    return false;
  }
};

Adjust to next business day:

el.beforeSelectCallback = (ctx) => {
  const day = ctx.date.getDay();
  if (day === 0 || day === 6) {
    const adjusted = new Date(ctx.date);
    adjusted.setDate(ctx.date.getDate() + (day === 0 ? 1 : 2));
    ctx.controller.showMessage('Adjusted to Monday', { type: 'info', autoHideMs: 3000 });
    return adjusted;
  }
};

Block past dates:

el.beforeSelectCallback = (ctx) => {
  const today = new Date();
  today.setHours(0, 0, 0, 0);
  if (ctx.date < today) {
    ctx.controller.showMessage('Past dates not allowed', { type: 'error' });
    return false;
  }
};

RANGE MODE VALIDATION
---------------------
Minimum nights requirement (keep the attempt visible):

el.beforeSelectCallback = (ctx) => {
  const nights = Math.floor((ctx.range.end - ctx.range.start) / 864e5);
  if (nights < 2) {
    ctx.markRangeInvalid();
    ctx.controller.showMessage('Minimum 2 nights required', { type: 'error' });
    return false;
  }
};

Adjust end date to checkout day (Sunday):

el.beforeSelectCallback = (ctx) => {
  const endDay = ctx.range.end.getDay();
  if (endDay !== 0) {
    const end = new Date(ctx.range.end);
    end.setDate(end.getDate() + (7 - endDay));
    ctx.controller.showMessage('Adjusted to Sunday checkout', { type: 'info' });
    return { start: ctx.range.start, end };
  }
};

Split around a blocked day (N ranges):

el.beforeSelectCallback = (ctx) => {
  if (!ctx.range) return;
  const hole = new Date(2026, 5, 15);
  if (ctx.range.start <= hole && ctx.range.end >= hole) {
    return [
      { start: ctx.range.start, end: new Date(2026, 5, 14) },
      { start: new Date(2026, 5, 16), end: ctx.range.end }
    ];
  }
};

ASYNC VALIDATION
----------------
Sync or async — a loader shows while a Promise is pending.

el.beforeSelectCallback = async (ctx) => {
  const response = await fetch('/api/check-availability', {
    method: 'POST',
    body: JSON.stringify({ start: ctx.range.start.toISOString(), end: ctx.range.end.toISOString() })
  });
  const data = await response.json();

  if (data.available) return;                     // accept
  if (data.suggestedEnd) {
    ctx.controller.showMessage('Adjusted to available dates', { type: 'info' });
    return { start: ctx.range.start, end: new Date(data.suggestedEnd) };
  }
  ctx.controller.showMessage('Dates not available', { type: 'error' });
  return false;
};

COMBINING VALIDATIONS
---------------------
el.beforeSelectCallback = async (ctx) => {
  const reject = (msg) => { ctx.controller.showMessage(msg, { type: 'error' }); return false; };
  const nights = Math.floor((ctx.range.end - ctx.range.start) / 864e5);

  if (nights < 2) return reject('Min 2 nights');
  if (nights > 14) return reject('Max 14 nights');
  if (!(await checkAvailability(ctx.range))) return reject('Not available');
  if (calculateCost(nights) > userBalance) return reject('Insufficient funds');
};

EXECUTION ORDER
---------------
1. Local validation (disabled dates, min/max)
2. beforeSelectCallback (if provided)
3. Selection finalized
4. select event (onSelect), then change event (onChange)

If step 1 or 2 rejects, the selection reverts.

ERROR HANDLING
--------------
el.beforeSelectCallback = async (ctx) => {
  try {
    if (!(await checkAvailability(ctx.range))) {
      ctx.controller.showMessage('Not available', { type: 'error' });
      return false;
    }
  } catch (error) {
    console.error('Validation error:', error);
    ctx.controller.showMessage('Unable to validate dates', { type: 'error' });
    return false;
  }
};

DEBUGGING
---------
el.beforeSelectCallback = (ctx) => {
  console.log('Validating:', ctx.mode, ctx.date ?? ctx.range);
  const result = performValidation(ctx);  // must follow the return contract
  console.log('Result:', result);
  return result;
};

BEST PRACTICES
--------------
1. Keep validation fast (cache API responses, pre-load data).
2. Explain rejections via ctx.controller.showMessage; suggest alternatives
   with data-action="custom" data-id="..." buttons.
3. Try/catch async code; return false on error.
4. Return values: nothing = accept, false = reject, Date/DateRange/DateRange[]
   = adjust, null = clear.

WEB COMPONENT
-------------
beforeSelectCallback is a PROPERTY (not an attribute):

✅ el.beforeSelectCallback = (ctx) => { ... };
❌ <web-daterangepicker before-select="...">  <!-- Not an attribute -->

Listening to `select` is AFTER the fact; use beforeSelectCallback to validate
BEFORE commit.

MONTH NAVIGATION: beforeMonthChangeCallback + getMonthDataCallback
=================================================================
CRITICAL: properties only.

beforeMonthChangeCallback(ctx) - runs BEFORE month navigation (not on the
  initial open). Return `false` to block; nothing to continue. Sync or async.

getMonthDataCallback(ctx) - loads data for the visible range on the INITIAL
  OPEN and after every accepted navigation. Returns
  { metadata?: Map<'YYYY-MM-DD', DayMetadata>, monthHeaders?: Map<'YYYY-MM', string> }
  (or null/nothing). Sync or async; a loader shows while pending.

PERFORMANCE BENEFIT
-------------------
WITHOUT getMonthDataCallback:
- getDateMetadataCallback called per rendered day (35-42 times per month)

WITH getMonthDataCallback:
- called ONCE per visible range (per column, or once for the whole grid in
  unified navigation) -> 1 API call, metadata cached and applied to all days

CONTEXT PARAMETER (MonthChangeContext)
--------------------------------------
{
  year: number,              // 2025
  month: number,             // 0-11 (January = 0)
  monthIndex: number,        // Which visible month column (0, 1, 2...)
  firstVisibleDate: Date,    // First date in calendar grid (may be prev month)
  lastVisibleDate: Date,     // Last date in calendar grid (may be next month)
  controller, element, presentation flags
}

DATE RANGE CALCULATION
----------------------
Single Month Mode:
- firstVisibleDate/lastVisibleDate span ~42 days (6 weeks around the target month)

Unified Navigation Mode:
- firstVisibleDate/lastVisibleDate span ALL visible months
- Example: 2×3 grid showing Jan-Jun = ~180 days -> one call for the whole grid

HOTEL AVAILABILITY EXAMPLE
---------------------------
el.getMonthDataCallback = async ({ firstVisibleDate, lastVisibleDate }) => {
  const response = await fetch('/api/hotel/availability', {
    method: 'POST',
    body: JSON.stringify({
      startDate: firstVisibleDate.toISOString().split('T')[0],
      endDate: lastVisibleDate.toISOString().split('T')[0],
      roomType: 'deluxe'
    })
  });
  const availability = await response.json();
  // [{ date: "2025-11-01", available: 5, price: 150 }, ...]

  const metadata = new Map();
  availability.forEach(day => {
    metadata.set(day.date, {
      isDisabled: day.available === 0,
      badgeText: day.available === 0 ? '✕' : `$${day.price}`,
      badgeClass: day.available === 0 ? 'sold-out' : 'available',
      dayTooltip: day.available === 0
        ? 'Sold out'
        : `${day.available} rooms available at $${day.price}/night`
    });
  });
  return { metadata };
};

MONTH HEADERS
-------------
el.getMonthDataCallback = async ({ year, month }) => {
  const key = `${year}-${String(month + 1).padStart(2, '0')}`;   // 'YYYY-MM', 1-based
  return { monthHeaders: new Map([[key, `${key} (12 rooms)`]]) };
};
monthHeaders win over getMonthHeaderCallback.

BLOCK NAVIGATION EXAMPLE
-------------------------
el.beforeMonthChangeCallback = async (ctx) => {
  try {
    const response = await fetch(`/api/check-period/${ctx.year}/${ctx.month + 1}`);
    const { dataReady } = await response.json();
    if (!dataReady) {
      ctx.controller.showMessage('Data not yet available for this period', { type: 'warning' });
      return false;
    }
  } catch (error) {
    console.error('Failed to check period:', error);
    ctx.controller.showMessage('Unable to load data for this period', { type: 'error' });
    return false;
  }
};

LOADING OVERLAY
---------------
Shown AUTOMATICALLY while either callback's Promise is pending.

METADATA PRIORITY
-----------------
1. Bulk metadata cache (from getMonthDataCallback)
2. getDateMetadataCallback (per-day callback)
3. specialDates (static array)

CACHE BEHAVIOR
--------------
- Initial open: the cache is replaced with the loaded data.
- Navigation: returned metadata/monthHeaders are MERGED into the caches;
  returning no metadata drops the metadata cache.
- The callback runs on every navigation — cache responses in your app if needed.

COMBINING WITH getDateMetadataCallback
---------------------------------------
el.getMonthDataCallback = async ({ firstVisibleDate, lastVisibleDate }) => {
  const metadata = new Map();
  // ... load pricing for all dates
  return { metadata };
};

el.getDateMetadataCallback = ({ date }) => {
  if (isHoliday(date)) {
    return { badgeText: '🎉', badgeClass: 'holiday', isDisabled: true };
  }
  return null;
};

LIMITATIONS
-----------
1. Properties only — cannot be set as HTML attributes.
2. Called every navigation — no built-in response caching.
3. Navigation waits for async callbacks — keep them fast (< 1s recommended).
4. No cancellation — once triggered, the callback runs to completion.
